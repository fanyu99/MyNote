# 系统调用

> 概述：系统调用是**应用程序请求操作系统内核服务**的统一入口。本篇梳理**系统调用是什么 → 为什么需要 → 分类 → 执行过程 → 操作系统体系结构（大内核 / 微内核）**。

---

## 一、什么是系统调用

系统调用是操作系统为应用程序提供的、访问 / 修改系统**共享资源**的**统一接口**。应用程序通过系统调用请求内核服务（如创建文件、申请内存）。

- 系统调用运行在**内核态**。
- 由**陷入指令（trap）**触发，属于**内中断**，是应用程序**主动**进入内核态的方式。

---

## 二、为什么需要系统调用

- 对系统**共享资源**进行**统一调度和协调**，防止并发共享时的数据冲突。
- 为应用程序提供访问内核服务的**统一接口**，隔离用户程序与内核、保证系统安全。

> [!note] 系统调用 vs 库函数
> 并非所有库函数都是系统调用：有的库函数只是对系统调用的**封装**（如 `printf` 底层常调用 `write`），有的库函数则完全不涉及内核（如部分数学函数）。

---

## 三、系统调用的分类

| 类别 | 功能 |
| --- | --- |
| 设备管理 | 完成设备的请求 / 释放 / 启动等 |
| 文件管理 | 完成文件的创建 / 读写 / 删除等 |
| 进程控制 | 完成进程的创建 / 阻塞 / 唤醒 / 撤销等 |
| 进程通信 | 完成进程之间的消息传递 / 信号传递 |
| 内存管理 | 完成内存的分配和回收 |

## 五、操作系统的体系结构

### 1. 操作系统的架构

操作系统由**非内核功能（GUI 等）**、**进程 / 存储 / 设备管理等功能**、**时钟管理 / 中断处理 / 原语（设备驱动、CPU 切换等）** 组成。

### 2. 大内核与微内核的区别

![[Pasted image 20261014160632.png]]

| 对比项 | 大内核（单内核） | 微内核 |
| --- | --- | --- |
| 内核包含 | 进程管理、存储管理、文件管理、设备管理等**主要功能** | 仅保留与硬件最紧密的**时钟管理、中断处理、原语**等最基本功能 |
| 运行状态 | 主要功能都在**核心态** | 大多数功能移到**用户态**，内核只留最小集合 |
| 优点 | **性能高**（态切换少） | **结构清晰、可靠、易扩展** |
| 缺点 | 内核庞大、结构混乱、**难以维护** | 频繁**态切换**、**执行效率较低** |

> 微内核下应用程序常常需要频繁切换 CPU 状态，而态切换开销较大，因此一般来说**大内核的执行效率更高**。
