# Modbus 协议

> 一种应用层串行通信协议（Master/Slave 主从架构），1979 年由 Modicon（今施耐德电气）提出。工业自动化领域事实标准，几乎所有 PLC、变频器、仪表、传感器、HMI 都支持。特点是**简单、开放、无版权费**。

---

## 一、三种常见传输模式

| 模式 | 物理层 | 特点 |
|------|--------|------|
| **Modbus RTU** | 串口 RS-485/RS-232 | 二进制紧凑，效率高，应用最广 |
| **Modbus ASCII** | 串口 RS-485/RS-232 | ASCII 十六进制字符，可读性好但效率低 |
| **Modbus TCP/IP** | 以太网 | 走 TCP **502 端口**，最通用，无需校验（TCP 自带） |

> 关键差异：**RTU 用二进制、ASCII 用文本、TCP 走以太网**。

---

## 二、主从（Master/Slave）工作方式

- **主站 Master（客户端）**：主动发起请求，只能有一个。
- **从站 Slave（服务器）**：被动响应，一条总线最多 **247** 个（地址 1~247，0 为广播）。
- 从站之间**不能直接通信**。

---

## 三、四种核心数据对象（寄存器体系）

一切通信围绕这 4 张表：

| 对象类型 | 名称 | 读写性 | 位宽 | 协议地址范围 | 功能码读取 |
|----------|------|--------|------|--------------|-----------|
| **线圈** Coil | 离散量输出 | 读/写 | 1 位 | 0x0000~0xFFFF | 01 |
| **离散输入** Discrete Input | 离散量输入 | 只读 | 1 位 | 0x0000~0xFFFF | 02 |
| **保持寄存器** Holding Register | 模拟量输出 | 读/写 | 16 位 | 0x0000~0xFFFF | 03 |
| **输入寄存器** Input Register | 模拟量输入 | 只读 | 16 位 | 0x0000~0xFFFF | 04 |

> **易混点**：协议中的偏移地址（0x0000）≠ PLC 的实际数据地址（如 40001）。PLC 习惯用 **1 起始**的地址（40001 表示第一个保持寄存器），协议帧里发的是**偏移量 0**。

---

## 四、常用功能码（Function Code）

| 功能码 | 含义 | 对应对象 |
|--------|------|---------|
| **01 (0x01)** | 读线圈 | 线圈 |
| **02 (0x02)** | 读离散输入 | 离散输入 |
| **03 (0x03)** | 读保持寄存器 | 保持寄存器 |
| **04 (0x04)** | 读输入寄存器 | 输入寄存器 |
| **05 (0x05)** | 写单个线圈 | 线圈 |
| **06 (0x06)** | 写单个寄存器 | 保持寄存器 |
| **15 (0x0F)** | 写多个线圈 | 线圈 |
| **16 (0x10)** | 写多个寄存器 | 保持寄存器 |
| **43 (0x2B)** | 读设备识别 | — |

---

## 五、报文帧格式（RTU 为例）

### 请求帧（主站 → 从站）

```
[从站地址 1B] [功能码 1B] [数据...N] [CRC 2B]
```

**功能码 03（读保持寄存器）请求示例**：

```
01  03  00 00  00 0A  C5 CD
│   │   │      │     └── CRC 校验
│   │   │      └────── 读取寄存器数量（0x000A = 10 个）
│   │   └───────────── 起始地址偏移（0x0000 = 从第 1 个保持寄存器开始）
│   └───────────────── 功能码 03 = 读保持寄存器
└───────────────────── 从站地址 01
```

### 响应帧（从站 → 主站）

```
01  03  14  [寄存器数据字节数 0x14=20字节]  [10个寄存器值共20B]  [CRC]
```

### 错误响应

从站返回**功能码最高位置 1**（`0x03 → 0x83`），后跟异常码：

| 异常码 | 含义 |
|--------|------|
| **01** | 非法功能码 |
| **02** | 非法数据地址 |
| **03** | 非法数据值 |
| **04** | 从站设备故障 |
| **06** | 从站忙，稍后重试 |

## 六、RTU 帧间隔（时序）

- 帧间空闲 ≥ **3.5 个字符传输时间**（切分帧）。
- 帧内字符间隔 **< 1.5 个字符传输时间**。
- 波特率 9600 时一个字符约 1ms，3.5 字符约 3.5ms。

> 上位机收发 RTU 需精确控制帧间延时，否则误判帧边界。

---

## 七、CRC 校验（RTU）

- **16 位循环冗余校验**，多项式 `0xA001`（反向）。
- 初值 `0xFFFF`，逐字节异或并右移 8 次，移出 1 时与 `0xA001` 异或。
- 结果**低字节在前**发送（小端）。

> TCP 模式无 CRC（TCP 自带校验）。

---

## 八、Modbus TCP 特殊点

- 端口固定 **502**。
- 多一个 **MBAP 头（7B）**：事务标识符(2B) + 协议标识符(2B,=0) + 长度(2B) + 单元标识符(1B)。
- **没有 CRC**。
- 从站地址 → **单元标识符 Unit ID**。
- 可一次带多个请求（用事务 ID 区分），比串口灵活。

---

## 九、上位机开发要点

1. **数据地址映射**：设备手册地址（如 40001）→ 协议偏移 `地址 - 40001`（保持寄存器）或 `地址 - 30001`（输入寄存器）。
2. **字节序**：16 位以上数据（float/int32）涉及高低字节顺序，各厂商可能不同，查手册确认。
3. **轮询机制**：主站周期轮询各从站，处理超时与重试。
4. **常用库**：Python `pymodbus`、C `libmodbus`、Node `modbus-serial`。
