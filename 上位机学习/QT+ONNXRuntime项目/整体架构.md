# QT + ONNXRuntime 项目整体架构

> 概述：项目采用**分层解耦**的架构——UI（QML）、任务编排（App / Manager / Worker）、检测执行（Detector）、帧源与绘制显示各自独立，层与层之间靠明确的数据结构通信。本页梳理整体分层与数据传输两条主线。

---

## 一、整体分层

```text
1. 顶层 UI（QML）
2. 中间层 DetectionApp    —— 把 DetectionManager 的各种结果 / 操作 / 错误反映到 QML 界面
3. 中间层 DetectionManager —— 将 App 的任务下发给 Worker，管理 DetectorWorker 的各种操作并处理结果
4. 执行层 DetectionWorker  —— 执行 Manager 下发的各种任务并返回结果 / 错误
5. 执行底层 Detector       —— 最底层的检测任务，返回检测结果
6. 绘画 + 显示 ImageProvider / DetectionRenderer —— 负责提供显示图和绘制检测框
7. 帧源 FrameSource        —— 提供帧源，返回 cv::Mat；目前支持文件帧源 FileFrameSource、海康相机帧源 HikCameraFrameSource
```

| 层 | 组件 | 职责 |
| --- | --- | --- |
| UI | QML | 界面交互与结果显示 |
| 中间层 | DetectionApp | 适配 Manager 与 QML 界面 |
| 中间层 | DetectionManager | 任务下发、Worker 管理与结果处理 |
| 执行层 | DetectionWorker | 在工作线程执行任务 |
| 执行层 | Detector | 最底层检测，产出检测结果 |
| 显示 | ImageProvider / DetectionRenderer | 显示图提供与检测框绘制 |
| 源 | FrameSource | 提供 `cv::Mat` 帧（文件 / 海康相机） |

---

## 二、数据传输分层

```text
1. 底层 Detector:    返回 DetectionResult（结果列表、错误信息）
2. 执行层 Worker:    获取 DetectionResult 后在工作线程绘制 QImage，再拷贝传给上层 Manager
3. 中间层 Manager:   获取 Worker 的结果并上报完成进度给 App
4. 中间层 App:       获取 Manager 的各种信息（错误 / 结果 / 进度等），交由 UI 显示
```

> [!note] 关键设计
> **绘制放在工作线程**（Worker 里生成 QImage 后拷贝上传），UI 线程只负责显示；跨线程传递的是**拷贝后的数据**，避免共享内存的生命周期问题（原理见 [[上位机学习/海康SDK/SDK缓冲区,图像数据生命周期]]）。
