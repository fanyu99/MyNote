# 数据库连接池 — 架构设计与高并发优化

> 当前实现位于 `D:\QT_Files\WindowsTest\Connection\`，基于 `QMutex` 单锁 + `ConnectionMeta` 元数据追踪。
> 本文档记录核心设计决策、已实现功能、以及面向 **1000+ QPS** 的优化方案。

---

## 1. 为什么要创建连接池？

- 减少 TCP 握手开销：复用已有连接，避免每次查询都做 DNS + TCP 三次握手 + 认证
- 控制并发连接数：防止数据库 `max_connections` 被打满
- 线程安全管理：Qt 要求每个线程使用独立的 `QSqlDatabase` 连接，连接池统一管理生命周期

---

## 2. 已实现功能

### 2.1 核心架构

| 组件 | 说明 |
|------|------|
| `ConnectionPool` | 单例模式，两阶段初始化 `Init(config)` + `Instance()` |
| `ScopedConnection` | RAII 包装器，构造获取、析构归还、支持移动语义、禁止拷贝 |
| `ConnectionMeta` | 连接元数据：Name、CreateTime、LastUsed |
| `QMutex` + `QWaitCondition` | 线程安全的获取/等待/归还机制 |
| `QAtomicInt ActiveCount` | 无锁追踪当前借出连接数 |
| 双定时器 | `pingTimer` 健康检查 + `shrinkTimer` 空闲/超期回收 |

### 2.2 连接池与线程池对照

| 线程池概念 | 连接池对应 |
|------------|-----------|
| `std::deque<std::function<void()>> tasks_` | `QQueue<ConnectionMeta> IdleConnections` |
| `cv.wait(lock, predicate)` | `WaitCV.wait(&Mutex, timeoutMs)` + while 循环防虚假唤醒 |
| `enqueue(task)` | `ReleaseConnection(meta)` 归还完整元数据 |
| `std::atomic<int> busynum_` | `QAtomicInt ActiveCount` |
| `~ThreadPool()` stop + join | `ShutdownAll()` 关闭空闲连接 + 警告活跃连接 |
| 启动时创建固定数量线程 | `Init(config)` 创建 `InitConnectionsNumber` 条连接 |
| *(无对应)* | `ConnectionMeta` 元数据追踪（创建时间、最后使用时间） |
| *(无对应)* | 两阶段初始化：`Init(config)` 存配置 → `Instance()` 触发构造 |

### 2.3 连接获取流程

```
GetConnection()
  ├─ 路径 1：队列非空 → dequeue → ActiveCount++ → 返回
  ├─ 路径 2：队列空 && 总数 < Max → 新建连接 → ActiveCount++ → 返回
  └─ 路径 3：池满 → while 循环 wait() → 超时返回 nullopt 或取到连接
```

### 2.4 RAII 包装器

```cpp
class ScopedConnection {
public:
    explicit ScopedConnection(ConnectionPool& pool);  // 构造时获取
    ~ScopedConnection();                               // 析构时自动归还

    ScopedConnection(const ScopedConnection&) = delete;            // 禁止拷贝
    ScopedConnection& operator=(const ScopedConnection&) = delete;

    ScopedConnection(ScopedConnection&& other) noexcept;           // 支持移动
    ScopedConnection& operator=(ScopedConnection&& other) noexcept;

    QSqlDatabase db() const;                     // 获取 QSqlDatabase
    void release();                              // 手动提前归还
    explicit operator bool() const noexcept;     // 检查是否有效
    std::optional<QString> connectionName() const noexcept;

private:
    ConnectionPool* pool_;
    std::optional<ConnectionMeta> meta_;         // 完整元数据
};
```

## 3. 高并发优化 TODO（1000+ QPS）

> 当前实现在桌面 WMS 场景（< 50 QPS）完全够用。以下优化面向高并发服务端场景。

### 3.1 当前瓶颈分析

| 瓶颈 | 影响 | 触发条件 |
|------|------|----------|
| `CreateNewConnection()` 在 `QMutex` 内做 TCP 握手 | 新建连接期间（10~200ms）所有线程阻塞 | 突发流量打满 `MaxConnections` |
| 单一 `QMutex` 全局串行 | Get/Release/定时器全部竞争同一把锁 | 1000+ QPS 锁争用成为吞吐上限 |
| `onPingTimer` 持锁遍历 N 条连接做 `SELECT 1` | 健康检查期间业务线程全部阻塞 | 空闲连接多或网络延迟高 |

---

### 3.2 P0：将 `CreateNewConnection` 移出临界区

**核心思路：** 用原子计数器 `ReservingCount` 预订名额，释放锁后在锁外做 TCP 握手，完成后入队并唤醒等待者。

#### 新增成员

```cpp
// ConnectionPool.h
QAtomicInt ReservingCount;  // 正在创建中、尚未入队的连接数
```

**连接总数公式：**
```
总连接数 = IdleConnections.size() + ActiveCount + ReservingCount
```

#### GetConnection 新建路径重写

```cpp
// 路径 2：还能新建，原子预订一个名额
int total = IdleConnections.size()
          + ActiveCount.loadRelaxed()
          + ReservingCount.loadRelaxed();

if (total < Configs->MaxConnectionsNumber) {
    ReservingCount.fetchAndAddRelaxed(1);  // 占位
    locker.unlock();                       // ← 释放锁

    // ── 锁外：TCP 握手 ──
    auto meta = CreateNewConnection();

    locker.relock();
    ReservingCount.fetchAndSubRelaxed(1);  // 取消占位

    if (meta.has_value()) {
        meta->LastUsed = QDateTime::currentDateTime();
        IdleConnections.enqueue(*meta);    // 入队供所有人使用
        WakeOneWaiterIfNeeded();           // 唤醒等待者
    } else {
        WaitCV.wakeOne();                  // 创建失败，让等待者重试
    }
    locker.unlock();

    return GetConnection();  // 递归重试
}
```

#### 时序对比

| | 旧（串行） | 新（并行） |
|---|---|---|
| 20 并发 × 50ms 握手 | **1000ms** | **~50ms** |
| P99 延迟 | ~1000ms | ~60ms |
| 期间其他 GetConnection | 全部阻塞 | 纳秒级取已有连接 |

#### 需要同步修改

- `onShrinkTimer` 总连接数计算加上 `ReservingCount.loadRelaxed()`
- 新增 `WakeOneWaiterIfNeeded()` 辅助方法：队列非空时 `wakeOne()`

### 3.3 P0：`onPingTimer` 锁外检测

**核心思路：** 锁内只做队列快照拷贝，释放锁后在锁外逐一 `SELECT 1`，再锁内合并结果。

```cpp
void ConnectionPool::onPingTimer()
{
    QMutexLocker locker(&Mutex);
    QQueue<ConnectionMeta> snapshot = IdleConnections;  // 快照
    IdleConnections.clear();
    locker.unlock();                                    // ← 释放锁

    QQueue<ConnectionMeta> alive;
    while (!snapshot.isEmpty()) {
        ConnectionMeta meta = snapshot.dequeue();
        QSqlDatabase db = QSqlDatabase::database(meta.Name);

        if (!db.isOpen()) {
            QSqlDatabase::removeDatabase(meta.Name);
            emit connectionBroken(meta.Name);
            continue;
        }

        QSqlQuery query(db);
        if (query.exec("SELECT 1")) {
            alive.enqueue(meta);
        } else {
            db.close();
            QSqlDatabase::removeDatabase(meta.Name);
            emit connectionBroken(meta.Name);
        }
    }

    locker.relock();
    // 合并：alive 追加到 IdleConnections（不能覆盖，期间可能有线程归还连接）
    while (!alive.isEmpty()) {
        IdleConnections.enqueue(alive.dequeue());
    }
    locker.unlock();
}
```

### 3.4 P1（远期）：锁粒度细化

> 仅在实测确认 P0 仍不够时再做。

| 方案 | 说明 | 适用场景 |
|------|------|----------|
| **读写锁** | `ActiveCount` 读取用原子操作替代，减少持锁时间 | 读多写少 |
| **分段连接池** | 按 `connectionId % N` 分散到多个子池，各自独立 `QMutex` | `MaxConnections` 很大 |
| **无锁队列** | `std::atomic` + CAS 维护空闲队列（Disruptor 模式） | 极端吞吐需求 |

### 3.5 P1（远期）：ODBC 替换为原生驱动

ODBC 桥接每查询额外增加 10-30% 延迟。1000+ QPS 场景应考虑：
- 编译 `qsqlmysql.dll` 使用 Qt 原生 MySQL 驱动
- 或换用 `mysql-connector-cpp`
