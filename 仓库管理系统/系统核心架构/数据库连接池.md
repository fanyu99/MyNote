# 数据库连接池 — 架构设计（技术探索，非必要组件）


> **⚠ 前置说明：** 数据库连接池在此桌面 WMS 项目中属于**技术探索**，而非必要组件。
> 桌面应用为单用户串行操作，使用单连接（`DatabaseManager` 单例）即可满足全部需求。
> 连接池的真正场景是 Web 服务/高并发后端。
>
> 本文档记录实现思路与设计决策，供面试中作为技术深度素材。

---

## 1. 为什么要创建连接池？（理论背景）

- 减少 TCP 握手开销：复用已有连接，避免每次查询都做 DNS + TCP 三次握手 + 认证
- 控制并发连接数：防止数据库 `max_connections` 被打满
- 线程安全管理：Qt 要求每个线程使用独立的 `QSqlDatabase` 连接，连接池统一管理生命周期

**桌面应用为什么不必要：** 桌面程序通常"建一次连接、用一整天"，没有高频短连接痛点。

## 2. 已实现功能（轻量版）

### 2.1 核心架构

| 组件 | 说明 |
|------|------|
| `ConnectionPool` | 单例模式，两阶段初始化 `Init(config)` + `Instance()` |
| `ScopedConnection` | RAII 包装器，构造获取、析构归还、支持移动语义、禁止拷贝 |
| `ConnectionMeta` | 连接元数据：Name、CreateTime、LastUsed |
| `QMutex` | 线程安全的获取/归还机制 |
| 无定时器 | 桌面场景无需健康检查和空闲回收（简化版） |

### 2.2 连接获取流程

```
GetConnection()
  ├─ 路径 1：队列非空 → dequeue → ActiveCount++ → 返回
  ├─ 路径 2：队列空 && 总数 < Max → 新建连接 → ActiveCount++ → 返回
  └─ 路径 3：池满 → 直接返回 nullopt（桌面低并发，不阻塞等待）
```

### 2.3 RAII 包装器

```cpp
class ScopedConnection {
public:
    explicit ScopedConnection(ConnectionPool& pool);  // 构造时获取
    ~ScopedConnection();                               // 析构时自动归还

    ScopedConnection(const ScopedConnection&) = delete;            // 禁止拷贝
    ScopedConnection& operator=(const ScopedConnection&) = delete;

    ScopedConnection(ScopedConnection&& other) noexcept;           // 支持移动
    ScopedConnection& operator=(ScopedConnection&& other) noexcept;

    QSqlDatabase db() const;                     // 获取 QSqlDatabase
    void release();                              // 手动提前归还
    explicit operator bool() const noexcept;     // 检查是否有效
    std::optional<QString> connectionName() const noexcept;

private:
    ConnectionPool* pool_;
    std::optional<ConnectionMeta> meta_;         // 完整元数据
};
```

## 3. 简化原因（面向桌面应用的重构）

原实现包含健康检查定时器（`SELECT 1` ping）、空闲回收定时器、`ReservingCount`、`QWaitCondition` 阻塞等待等机制——这些全是面向高并发服务端的设计。

当前轻量版的简化点：

| 移除项 | 原因 |
|--------|------|
| 健康检查定时器 | 桌面应用使用时长短，无需定期保活 |
| 空闲回收定时器 | 连接数少且可控，无需自动缩容 |
| `QWaitCondition` 阻塞等待 | 低并发下池满概率极低，直接返回 nullopt 更简洁 |
| `QAtomicInt` → 普通 `int` | 只在单线程获取/归还连接，无需原子操作 |

## 4. 面试要点

### 问：你们项目用了数据库连接池？

> "项目中我实现了一个轻量数据库连接池用于技术探索。桌面应用实际只需要一个永久连接即可，我实现连接池的目的是理解连接复用、RAII 生命周期管理、以及资源池化等设计模式。如果以后转做后台服务，这个设计可以直接复用。"

### 问：连接池与普通单连接有什么区别？

> "连接池维护一组可复用的数据库连接，适合高并发场景。桌面应用没有多个线程同时请求数据库的压力，单连接完全够用。连接池解决的是 Web 服务的痛点——每次 HTTP 请求创建 TCP 连接太昂贵。"

## 5. 何时需要真正的连接池？

如果后续将此项目扩展为：
- REST API 后端服务（`QtHttpServer` 或 `crow` 等）
- 多线程并发导出报表
- 定时任务 + 用户操作并发

届时连接池的完整方案（含健康检查、超时重试、空闲回收）将成为必要组件。
