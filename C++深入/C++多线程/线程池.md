# C++ 线程池

本篇梳理线程池的核心设计思路、一个完整可编译的基础实现，以及使用 `std::future` 和条件变量时需要注意的关键原则。

> [!important] 核心主线
> **线程池的本质是“固定数量的工作线程 + 任务队列”。**
> 关键设计原则是：用锁保护共享状态（队列、停止标志），把任务执行放在锁外，避免在持锁时阻塞或执行耗时操作。

---

## 一、线程池的基本思路

```text
程序启动
  ├── 创建固定数量的工作线程
  └── 创建任务队列

提交任务
  └── 任务进入队列

工作线程
  ├── 队列有任务：取出并执行
  └── 队列没任务：等待

程序关闭
  ├── 通知线程池停止接收任务
  ├── 唤醒所有工作线程
  ├── 执行完队列中剩余任务
  └── 等待所有工作线程退出
```

> [!note] 重要思想
> 锁只用来保护共享状态和数据；任务、回调、耗时操作等尽量放在锁外执行。

## 二、基础线程池的完整实现

```cpp
#include <condition_variable>
#include <cstddef>
#include <functional>
#include <future>
#include <mutex>
#include <queue>
#include <stdexcept>
#include <thread>
#include <type_traits>
#include <utility>
#include <vector>

class ThreadPool {
public:
    explicit ThreadPool(std::size_t thread_count) {
        if (thread_count == 0) {
            throw std::invalid_argument(
                "thread_count must be greater than zero");
        }

        workers_.reserve(thread_count);
        // 创建线程
        for (std::size_t i = 0; i < thread_count; ++i) {
            workers_.emplace_back([this] {
                worker_loop();
            });
        }
    }

    ThreadPool(const ThreadPool&) = delete;
    ThreadPool& operator=(const ThreadPool&) = delete;

    ~ThreadPool() {
        shutdown();
    }

    // 提交任务函数
    template <typename F, typename... Args>
    auto submit(F&& function, Args&&... args)
        -> std::future<std::invoke_result_t<F, Args...>>
    {
        using Result = std::invoke_result_t<F, Args...>; // 推导函数结果
        // 绑定参数到函数中；也可以用 std::tuple 打包参数，再用 std::apply() 执行
        auto bound_task = std::bind(
            std::forward<F>(function),
            std::forward<Args>(args)...
        );
        // 打包任务
        auto packaged_task =
            std::make_shared<std::packaged_task<Result()>>( // packaged_task 只能移动，用智能指针保存
                std::move(bound_task)
            );
        // 获取任务执行的结果 future
        std::future<Result> result = packaged_task->get_future();

        {
            std::lock_guard<std::mutex> lock(mutex_); // 加锁保护队列

            if (stopping_) {
                throw std::runtime_error(
                    "submit called after ThreadPool shutdown");
            }

            tasks_.emplace([packaged_task] {
                (*packaged_task)();
            });
        }
        // 唤醒一个消费者
        condition_.notify_one();
        return result;
    }

    void shutdown() {
        {
            std::lock_guard<std::mutex> lock(mutex_);

            if (stopping_) {
                return;
            }

            stopping_ = true;
        }

        condition_.notify_all();
        // 等待所有线程退出
        for (std::thread& worker : workers_) {
            if (worker.joinable()) {
                worker.join();
            }
        }
    }

private:
    void worker_loop() {
        while (true) {
            std::function<void()> task;

            {
                std::unique_lock<std::mutex> lock(mutex_);
                // 等待直到 1. 停止 或 2. 队列不为空
                condition_.wait(lock, [this] {
                    return stopping_ || !tasks_.empty();
                });
                // 如果停止且队列空，就返回
                if (stopping_ && tasks_.empty()) {
                    return;
                }
                // 取任务
                task = std::move(tasks_.front());
                tasks_.pop();
            }
            // 在锁外执行任务，防止死锁
            task();
        }
    }

    std::vector<std::thread> workers_;
    std::queue<std::function<void()>> tasks_;

    std::mutex mutex_;
    std::condition_variable condition_;
    bool stopping_ = false;
};
```

> [!warning] 注意
> `std::packaged_task` 不可复制，只能移动。这里用 `std::shared_ptr` 把它包装后存入 `std::function` 的 lambda 中，这样既能放入队列，又能安全地在多个地方引用。

## 三、关于 `std::future` 需要知道的事

1. `future.get()` 会使当前线程阻塞等待，所以**不要在持有锁的时候调用可能阻塞的 `get()`**。
2. `future.get()` 返回的结果可能携带异常，调用方需要用 `try/catch` 处理。
3. `future.get()` 只能调用一次；如果需要共享结果，使用 `std::shared_future`。

## 四、线程池各板块的详细流程

### 4.1 提交任务

```text
用户的任务
    │
    ▼
包装任务与结果
    │
    ▼
取 future
    │
    ▼
包装为任务队列能够接受的任务
    │
    ▼
放入任务队列并通知工作线程
```

### 4.2 工作线程

```text
等待有任务 / 停止
    │
    ▼
加锁从共享任务中取得任务
    │
    ▼
解锁
    │
    ▼
执行任务
    │
    ▼
（循环）等待有任务 / 停止
```

### 4.3 线程池关闭

```text
持有锁，设置标志位为停止，通知所有工作线程
    │
    ▼
拒绝新任务
    │
    ▼
等待工作线程处理完任务并退出（join）
```

> [!important] 需要记住的原则
> 1. 从队列取任务时持锁，执行任务不持锁。
> 2. 任务结果可以使用 `std::future` 返回，任务出现的异常可通过 `future.get()` 观察。
> 3. 停止状态和队列入队操作必须进行同步，避免关闭与提交之间的竞态。
> 4. 线程池析构时必须处理工作线程的退出和 `join`。
> 5. `future.get()` 只能获取一次结果，且可能阻塞线程；不要在持有工作线程必需锁时盲目使用 `future.get()`。

## 五、核心总结

### 5.1 一句话主线

```text
线程池 = 固定工作线程 + 共享任务队列 + 条件变量同步
submit  →  打包任务 + 入队 + 通知
worker  →  等待唤醒 + 持锁取任务 + 解锁执行
shutdown → 设停止标志 + 唤醒所有线程 + join 等待退出
```

### 5.2 易错点

- 不要在持锁时执行耗时任务或调用可能阻塞的 `future.get()`。
- `packaged_task` 不可复制，需要用移动或 `shared_ptr` 间接管理。
- 停止标志 `stopping_` 必须在锁内读取和修改，与 `submit` 形成互斥。
- `shutdown()` 在 `join` 前必须先 `notify_all()`，否则工作线程可能永远等待。
- 析构函数中必须保证所有工作线程已 `join`，否则程序会 `std::terminate()`。
