# 菱形继承与虚继承

承接 [[对象大小,内存对齐和继承布局|对象大小、内存对齐与继承布局]] 中的多继承布局，本篇处理多继承最经典的一个问题：**菱形继承**带来的数据冗余与二义性，以及用**虚继承**共享同一份基类子对象的方法，最后说明虚继承在构造顺序、初始化责任和对象布局上的代价。

> [!important] 核心主线
> **菱形继承的病根是"同一份基类在对象里出现了两次"。**
> 用 `::` 消歧只是绕过问题；**虚继承**让最终对象只保留**一份**共享的虚基类子对象，才是根治——但代价是额外的偏移表指针，以及"虚基类只由最终派生类初始化"这条特殊规则。

---

## 一、菱形继承与二义性

```cpp
class A {
public:
    int a;
};

class B : public A {
public:
    int b;
};

class C : public A {
public:
    int c;
};

class D : public B, public C {
public:
    int getValue() const {
        return a; // 编译错误：a 有二义性
    }
};
```

此时 `D` 对象通常包含**两个 `A` 基类子对象**（分别来自 `B` 与 `C`）：

```text
D 对象
├── B 子对象
│   └── A 子对象（B::a）
└── C 子对象
    └── A 子对象（C::a）
```

这带来两个问题：

1. **数据冗余**：同一份 `A` 的数据在对象里出现了两次；
2. **二义性**：在 `D` 中访问 `a` 时，编译器无法确定指的是 `B::a` 还是 `C::a`。

> [!warning] 注意：这是编译期错误
> `return a;` 会因名字二义性**编译失败**，而**不是**运行到那一行才出错。
> 需要用作用域运算符 `::` 显式指定访问哪一份：
>
> ```cpp
> int getValueFromB() const { return B::a; }
> int getValueFromC() const { return C::a; }
> ```

> [!warning] 注意：成员可见性也要保证
> 上例中 `a` 必须是 `public`（或 `protected`）才能真正触发"二义性"这一步。
> 若写成 `class A { int a; };` 这样的默认私有成员，`D` 连访问权限都没有，会先报**访问权限**错误，测试不到二义性本身。

## 二、虚继承：共享同一份基类子对象

只要让 `B`、`C` **虚继承** `A`，最终对象里就只会有一份 `A`：

```cpp
class A {
public:
    int a;
};

class B : virtual public A {  // 关键字 virtual 加在继承处
public:
    int b;
};

class C : virtual public A {
public:
    int c;
};

class D : public B, public C {
public:
    int getValue() const {
        return a; // OK：只有一份 A，无二义性，也不需要 ::
    }
};
```

布局变为：

```text
D 对象（虚继承）
├── B 子对象
│   └── vbptr  →  指向虚基类偏移表
└── C 子对象
    └── vbptr  →  指向虚基类偏移表
        （B、C 各自额外多出一个指针）
└── A 子对象（全对象共享唯一一份）
    └── a
```

对比两种写法：

| 写法 | `D` 中 `A` 子对象的份数 | `return a;` | 数据冗余 |
|---|---|---|---|
| `class B : public A` | 2 份 | 二义性，编译错误 | 有 |
| `class B : virtual public A` | 1 份 | 合法，无需 `::` | 无 |

> [!note] 说明
> `virtual` 在这里修饰的是**继承关系**，和虚函数的 `virtual` 是两回事，只是共用了关键字。

## 三、构造顺序与"谁负责初始化虚基类"

### 3.1 构造顺序：虚基类最先

```cpp
#include <iostream>

class A {
public:
    A() { std::cout << "A "; }
};

class B : virtual public A {
public:
    B() { std::cout << "B "; }
};

class C : virtual public A {
public:
    C() { std::cout << "C "; }
};

class D : public B, public C {
public:
    D() { std::cout << "D "; }
};

int main() {
    D d;
}
```

输出为：

```text
虚继承   →  A B C D
```

也就是：**虚基类 `A` 最先构造**，且只构造一次；然后才是非虚基类 `B`、`C`（按声明顺序），最后是 `D` 自己。析构顺序与之相反。

作为对比，把 `virtual` 去掉（普通菱形继承）后输出是：

```text
普通继承 →  A B A C D   ← A 出现了两次
```

> [!important] 重点
> 虚基类**先于**非虚基类构造，且整个对象中只构造一次。

### 3.2 虚基类只由"最终派生类"初始化

这是虚继承最容易出错的一条规则。看这段代码：

```cpp
#include <iostream>

class A {
public:
    A(int x) : a(x) { std::cout << "A(" << x << ") "; }
    int a;
};

class B : virtual public A {
public:
    B(int x) : A(x) { std::cout << "B "; }  // 当 B 只是中间类时，这个 A(x) 会被忽略
};

class C : virtual public A {
public:
    C(int x) : A(x) { std::cout << "C "; }
};

class D : public B, public C {
public:
    // 真正决定 A 怎么构造的是这里
    D(int x) : A(x), B(x), C(x) { std::cout << "D "; }
};

int main() {
    D d(7);
}
```

输出为：

```text
A(7) B C D
```

可以看到：`B(7)`、`C(7)` 里写的 `A(x)` **都没有生效**，`A` 只被构造了一次，用的是 `D` 传入的参数。原因很直观——一个对象里 `A` 只有一份，如果 `B`、`C` 都能初始化它，就会互相覆盖。

> [!warning] 注意：中间类仍必须写出对虚基类的初始化
> 虽然中间类的初始化会被忽略，但**在语法上它仍必须能初始化虚基类**。
> 例如若 `A` 没有默认构造函数，那么 `B(int x) : A(x) {}` 里的 `A(x)` 就不能省——否则 `B b(1);` 单独使用时编译不过（会报 `no matching function for call to 'A::A()'`）。
>
> 结论：**每个类都要能独立地初始化虚基类，即使作为中间层时这句话会被忽略。**

## 四、对象布局与开销

为什么虚继承需要额外的指针？关键在于：编译器**无法在编译期确定虚基类子对象的偏移**。一个 `B*` 可能指向独立的 `B` 对象，也可能指向 `D` 对象内部的 `B` 子对象，两种情况下 `A` 的偏移并不相同。

因此，虚继承的子对象里通常会多放一个**虚基类偏移表指针（vbptr）**，在运行期算出虚基类的地址：

```text
D 对象（概念图）
+--------------------------+
| B 部分                   |
|   vbptr_B  → 偏移表       |  ← 记录 A 相对本部分的偏移
|   int b                  |
+--------------------------+
| C 部分                   |
|   vbptr_C  → 偏移表       |
|   int c                  |
+--------------------------+
| int d                    |
+--------------------------+
| A 子对象（唯一一份）        |
|   int a                  |
+--------------------------+
```

> [!warning] 注意：布局由实现决定
> 上面只是**概念图**。虚基类的实际位置、偏移表的组织方式由编译器与 ABI 决定，不同平台可能不同，不要依赖具体偏移。

> [!warning] 注意：虚继承通常让对象更大
> 虚继承省下的是"重复的 `A` 数据"，但每个虚继承的子对象往往要多一个 `vbptr`，**访问虚基类成员还多一次间接寻址**。
> 因此 `sizeof(D)` 往往**不会比普通菱形继承小，反而可能更大**——例如本机 MinGW g++ 15.2 上，一个不含数据成员的菱形虚继承结构约占 16 字节，而等价的普通菱形继承仅 2 字节。
> 结论：**虚继承是解决二义性的手段，不是省内存的手段。**

## 五、虚继承下的类型转换

虚继承会给类型转换带来一条硬性限制：

```cpp
D obj;
A* pa = &obj;                    // 派生 → 虚基类：OK（可能需要在运行期调整地址）
D* p1 = static_cast<D*>(pa);     // 编译错误：不能从虚基类 static_cast 向下转型
D* p2 = dynamic_cast<D*>(pa);    // OK：必须用 dynamic_cast
```

编译器会明确报错：

```text
error: cannot convert from pointer to base class 'A'
       to pointer to derived class 'D' because the base is virtual
```

原因是虚基类的偏移在编译期无法唯一确定，`static_cast` 生成不出这个转换，只能交给运行期查表的 `dynamic_cast`——正好呼应 [[对象切片,类型转换,dynamic_cast|对象切片、类型转换与 dynamic_cast]] 里的结论：

> [!important] 重点
> 从**虚基类**向下转型，`static_cast` 不可用（编译错误），**必须使用 `dynamic_cast`**。

## 六、核心总结

### 6.1 一句话主线

```text
菱形继承的问题 → 基类子对象出现两份：数据冗余 + 访问二义性
消歧的临时手段 → 作用域运算符 ::
根治手段       → 虚继承 virtual public：整个对象只保留一份虚基类子对象
虚继承的代价   → 额外 vbptr、成员访问多一次间接寻址、虚基类由最终派生类初始化
```

### 6.2 速查表

| 问题 | 答案 |
| --- | --- |
| 菱形继承的两个问题？ | 数据冗余、成员访问二义性 |
| `return a;` 报错发生在什么时候？ | 编译期（名字二义性） |
| 不想改继承关系，怎么消歧？ | 用 `B::a` / `C::a` 显式指定 |
| 虚继承怎么写？ | `class B : virtual public A` |
| 虚继承后 `D` 里有几份 `A`？ | 只有 1 份 |
| 虚基类什么时候构造？ | 最先构造，且只构造一次 |
| 谁负责初始化虚基类？ | **最终派生类**；中间类的初始化会被忽略 |
| 中间类还需要写虚基类的初始化吗？ | 需要，否则该类单独使用时会编译失败 |
| 虚继承会让对象变小吗？ | 通常不会，甚至更大（多了 vbptr） |
| 从虚基类向下转型用什么？ | `dynamic_cast`，`static_cast` 是编译错误 |

### 6.3 易错点

- 以为 `::` 解决了菱形继承——它只消除二义性，**两份 `A` 依然存在**，要根治得用虚继承。
- 以为中间类构造函数的 `A(x)` 会生效——当它是中间层时**会被忽略**，但**不能省略**。
- 以为虚继承"更省内存"——它换来的是正确性，不是空间。
- 想对虚基类用 `static_cast` 向下转型——直接编译不过，必须 `dynamic_cast`。
