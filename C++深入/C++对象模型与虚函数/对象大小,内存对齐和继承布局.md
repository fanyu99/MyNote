# 对象大小、内存对齐与继承布局

承接 [[C++对象模型和虚函数|对象模型与虚函数]]，本篇从"一个对象到底占多少内存"出发：先看 `sizeof` 统计什么、空类为什么是 1 字节，再讲内存对齐与填充规则，最后落到虚函数、单继承、多继承下的对象布局。

> [!important] 核心主线
> **对象大小 = 非静态数据成员 + 隐藏数据（如 `vptr`） + 对齐填充。**
> 记住这条式子，本课后面的所有结果都可以自己推导出来。

---

## 一、`sizeof` 统计什么

### 1.1 直接用途

`sizeof` 用于获取一个类型或对象所占用的字节数：

```cpp
int val = 10;
std::cout << sizeof(val) << "\n";
```

通常输出 4，但具体字节数随操作系统和平台而不同。

### 1.2 为什么成员函数不计入对象大小

```cpp
class Student {
public:
    void study() {}
private:
    int age;
};
```

这里通常 `sizeof(Student) == 4`。那为什么 `study()` 的代码大小没有被统计？

> [!note] 说明
> 普通函数的代码不保存在每个对象里，而是保存在***内存模型中的程序代码区***。对象内部只保存"每个对象各有一份"的数据。

### 1.3 结论

> [!important] 重点：`sizeof` 统计什么
> **通常包含：**
> - 非静态数据成员；
> - 编译器为实现功能而加入的隐藏数据，例如 `vptr`；
> - 为内存对齐加入的填充字节。
>
> **通常不包含：**
> - 普通成员函数的代码；
> - 静态成员变量 / 静态成员函数；
> - 类的名字；
> - 成员函数的参数和局部变量。

## 二、空类的大小

```cpp
class Empty {};
```

一个空类的大小通常输出 `1`。

原因是 C++ 要求两个不同的完整对象拥有**不同的地址**。如果空类大小为 0，那么对象数组按下标访问时就会出现问题：

```cpp
&Emptys[0];
&Emptys[1];
// ...
```

> [!important] 结论
> 编译器会给空类对象安排至少一个字节，让不同对象拥有不同地址，即**占位字节**。

## 三、内存对齐

### 3.1 什么是内存对齐

CPU 访问某些对齐地址上的数据通常更加方便高效。为了达成这个目的，编译器会在一定偏移地址上填充字节，即**内存对齐**。

- **对齐目标**：通常为满足类中最大的成员对齐要求的倍数；
- **填充位置**：通常会在对象尾部填充，以确保对象放进数组时每个元素都正确对齐。

```cpp
class E {
public:
    char a;
    int b;
};
```

此时 `sizeof(E)` 通常是 8 而不是 5。假设 `int` 占 4 字节，它需要从能被 4 整除的地址开始，即 `0, 4, 8, 12 ...`。

按声明顺序 `char` → `int`，如果不做对齐，`b` 会从偏移 1 开始被访问，没有落在 4 字节边界上：

```text
偏移       内容
0          char a
1          int b   ← 未对齐

示意图：
+-------------+ 偏移 0
| char a      | 1 字节
+-------------+ 偏移 1
| int b       | 4 字节（未对齐，不推荐）
+-------------+ 偏移 5
```

因此编译器会在偏移 1～3 填充字节，让后续 CPU 对 `b` 的访问更方便：

```text
偏移       内容
0          char a
1～3       填充字节
4～7       int b

示意图：
+-------------+ 偏移 0
| char a      | 1 字节
+-------------+ 偏移 1
| padding     | 3 字节
+-------------+ 偏移 4
| int b       | 4 字节
+-------------+ 偏移 8
```

### 3.2 成员的声明顺序会影响对象大小

由上面一点可知，成员的声明顺序会影响对象大小。

```cpp
class A {
public:
    char a;
    int b;
    char c;
};

class B {
public:
    int b;
    char a;
    char c;
};
```

**对于 `A`**，需要内存对齐：

```text
偏移 0       ：char a       1 字节
偏移 1～3    ：padding      3 字节
偏移 4～7    ：int b        4 字节
偏移 8       ：char c       1 字节
偏移 9～11   ：padding      3 字节
```

对象尾部要填充到 `int` 大小的倍数，因此 `sizeof(A) == 12`。

**对于 `B`**，成员已按大小降序排列，此时仅需在尾部填充 2 个字节：

```text
偏移 0～3    ：int b        4 字节
偏移 4       ：char a       1 字节
偏移 5       ：char c       1 字节
偏移 6～7    ：padding      2 字节
```

最终 `sizeof(B) == 8`。

> [!important] 结论
> 同样的成员，仅改变声明顺序，`12` 就降到了 `8`。——**声明顺序会实打实地影响对象大小。**

### 3.3 工程经验

> [!tip] 排列原则
> 把对齐要求高、体积大的成员放在前面，较小的成员集中放在后面。

```cpp
class Better {
public:
    std::string name; // 通常比 double 还大
    double score;
    int age;
    char level;
    bool passed;
};
```

### 3.4 `alignof` 查看类型的对齐要求

```cpp
std::cout << sizeof(char) << " ";
std::cout << alignof(char);
```

通常输出 `1 1`。在常见的 64 位环境中：

```text
sizeof(char)    = 1     alignof(char)   = 1
sizeof(int)     = 4     alignof(int)    = 4
sizeof(double)  = 8     alignof(double) = 8
```

`alignof` 用来查看一个对象通常应当从多大的边界对齐的地址开始。

### 3.5 `offsetof` 查看成员偏移

```cpp
#include <cstddef>
#include <iostream>

struct Data {
    char a;
    int b;
    char c;
};

int main() {
    std::cout << "sizeof(Data) = " << sizeof(Data) << '\n';
    std::cout << "a offset = " << offsetof(Data, a) << '\n';
    std::cout << "b offset = " << offsetof(Data, b) << '\n';
    std::cout << "c offset = " << offsetof(Data, c) << '\n';
}
```

通常结果为：

```text
sizeof(Data) = 12
a offset = 0
b offset = 4
c offset = 8

偏移 0       ：a
偏移 1～3    ：填充
偏移 4～7    ：b
偏移 8       ：c
偏移 9～11   ：尾部填充
```

> [!warning] 注意
> `offsetof` 通常只用于普通的、没有复杂继承和虚函数的 `struct`，不要用于检查复杂的多态类型。

## 四、指针大小与程序位数

一般普通对象指针的大小：

```cpp
// 常见的 64 位程序
sizeof(void*) == 8
// 常见的 32 位程序
sizeof(void*) == 4
```

指针大小取决于**程序位数**，而不是"指针指向什么类型的数据"。

## 五、虚函数如何影响对象大小

```cpp
class Normal {
public:
    int value;
};

class Abnormal {
public:
    virtual void print() {}
    int value;
};
```

此时：

```text
sizeof(Normal)   == 4
sizeof(Abnormal) == 16
```

为什么 `Abnormal` 是 16？

```text
vptr：       8 字节   ← 隐藏的虚函数表指针
int value：  4 字节
尾部填充：   4 字节   ← 满足 vptr 的 8 字节对齐要求
总计：      16 字节
```

布局示意图：

```text
Abnormal 对象：
偏移 0～7
+------------------+
| vptr             | 8 字节
+------------------+
偏移 8～11
+------------------+
| int value        | 4 字节
+------------------+
偏移 12～15
+------------------+
| padding          | 4 字节
+------------------+
```

那么增加虚函数个数，对象会不会变大？

> [!important] 重点
> 在**单继承**情况下通常不会。一个对象只有一个 `vptr`，它指向同类对象**共有**的虚函数表 `vtable`；增加虚函数只是给虚函数表**增加槽位**，不会给对象增加新的 `vptr`。

关于 `vptr`、`vtable` 的调用链，详见 [[C++对象模型和虚函数#三、虚函数|对象模型与虚函数 · 三、虚函数]]。

> [!warning] 注意：大小依赖实现
> `vptr` 为 8 字节是**常见 64 位实现**的结果，并非 C++ 标准规定的固定值。具体大小与编译器、平台和 ABI 有关。

## 六、静态成员变量不属于对象本身

```cpp
class Counter {
public:
    static int total;
    int value;
};

int Counter::total = 0;
```

此时 `sizeof(Counter)` 通常为 4 而不是 8。静态成员 `total` 为 `Counter` 类所共有，放在**静态存储区**：

```text
Counter c1：           Counter c2：           类的静态存储：
+-----------+          +-----------+          +----------------+
| value     |          | value     |          | Counter::total |
+-----------+          +-----------+          +----------------+
```

## 七、单继承对象布局

```cpp
class Base {
public:
    virtual int getValue(); // vptr 8 字节
private:
    int baseValue;          // int  4 字节
    char a;                 // char 1 字节
    // +3 字节填充
};

class Derived : public Base {
    // Base 部分：16 字节
public:
    int getValue() override;
public:
    int derivedValue;       // int  4 字节
    // +4 字节填充
};
```

可以理解为：

```text
Base 对象：
+------------------------+
| vptr          8 字节   |
| baseValue     4 字节   |
| a             1 字节   |
| 内存对齐填充  3 字节   |
+------------------------+

Derived 对象：
+------------------------+
| Base 子对象：          |
|   vptr        8 字节   |
|   baseValue   4 字节   |
|   a           1 字节   |
|   内存对齐    3 字节   |
+------------------------+
| derivedValue  4 字节   |
| 内存对齐      4 字节   |
+------------------------+
```

最终：

```cpp
sizeof(Base)    == 16
sizeof(Derived) == 24
```

> [!important] 重点：指针指向哪里
> 派生类的 `vptr` 放置在它的基类子对象中。
> - 基类指针指向派生类对象时，实际指向**派生类中基类子对象的起始地址**；
> - 派生类指针指向的是**派生类整体的起始地址**。

单继承中的布局细节可对照 [[C++对象模型和虚函数#七、继承下的对象布局|对象模型与虚函数 · 七、继承下的对象布局]]。

## 八、多继承对象布局

根据单继承布局，可以推导出多继承布局：

```cpp
class A {
public:
    virtual void functionA() {}
    int a;
};

class B {
public:
    virtual void functionB() {}
    int b;
};

class C : public A, public B {
public:
    void functionA() override {}
    void functionB() override {}
    int c;
};
```

概念布局为：

```text
C 对象：
+----------------------+
| A 子对象             |
|   vptr_A             |
|   int a              |
|   padding            |
+----------------------+
| B 子对象             |
|   vptr_B             |
|   int b              |
|   padding            |
+----------------------+
| int c                |
| padding              |
+----------------------+
```

> [!important] 重点：指针调整
> 多继承下，不同类型的基类指针可能指向**同一个完整对象的不同地址**，其实际指向的就是派生类中对应的基类子对象。
> 因此，**改变基类指针的类型可能会改变指针实际指向的地址**（指针调整）。详见 [[C++对象模型和虚函数#^d31090|对象模型与虚函数 · RTTI]]。

## 九、`this` 指针是什么

`this` 是一个隐式的指针：通常类型为 `ClassName* const`（普通成员函数）或 `const ClassName* const`（const 成员函数），指向调用该成员函数的对象本身（不可改指向）。

> [!note] 关键点
> `this` **不是对象的数据成员**，不占对象的 `sizeof`，而是编译器在调用成员函数时自动传入的一个参数。

主要用途：

- 区分同名的成员变量：当形参与成员变量同名时，必须写 `this->member`；
- 返回对象自身以实现链式调用：例如 `return *this`；
- 在成员函数中获取对象的地址：如传递给外部函数或容器。

## 十、核心总结

### 10.1 一句话主线

```text
对象大小 = 非静态数据成员
         + 隐藏数据（如 vptr）
         + 对齐填充（成员之间 + 对象尾部）
```

### 10.2 速查表

| 问题 | 答案 |
| --- | --- |
| `sizeof` 统计什么？ | 非静态数据成员 + 隐藏数据（如 `vptr`）+ 对齐填充 |
| `sizeof` 不统计什么？ | 普通成员函数、静态成员、局部变量、类名 |
| 空类为什么是 1 字节？ | 让不同的完整对象拥有不同地址 |
| 为什么成员大小之和 ≠ 对象大小？ | 编译器可能在成员之间和对象尾部插入填充字节 |
| 为什么对象尾部也要填充？ | 让对象数组中的每个元素都满足正确的对齐要求 |
| 虚函数为什么增大对象？ | 带虚函数的对象通常需要保存一个隐藏的 `vptr` |
| 多写几个虚函数会多出多个 `vptr` 吗？ | 单继承通常不会，只增加虚函数表的槽位 |
| 派生类对象里面有什么？ | 基类子对象 + 派生类自己的成员 + 可能的填充与隐藏数据 |
| `this` 占对象空间吗？ | 不占，是编译器隐式传入的参数 |

### 10.3 易错点

- 手工分析偏移时，别忘**尾部填充**：有效偏移范围是 `0 ~ sizeof-1`。
- `vptr` 的 8 字节、各类型的大小都是**常见 64 位实现**的结果，不是标准保证，换个平台/编译器可能不同。
