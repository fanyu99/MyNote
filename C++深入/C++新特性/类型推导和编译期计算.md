# 类型推导与编译期计算

承接 [[右值引用,移动语义,完美转发|右值引用、移动语义与完美转发]] 中"引用折叠与万能引用"的结论，本篇补齐 `auto` / `decltype` 的推导规则与易错点，再延伸到类型萃取（type traits）与编译期计算，说明它们如何与模板、`if constexpr` 配合。编译期常量的完整规则见 [[constexpr编译常量|constexpr 编译期常量]]。

> [!important] 核心主线
> **`auto` 走的是"模板按值推导"那套规则，`decltype` 则是"精确报告表达式类型"的另一套规则——两者最容易在引用与 `const` 上产生分歧。**
> `decltype(auto)` 是二者的折中：像 `auto` 一样书写，却像 `decltype` 一样精确保留类型。

---

## 一、`auto` 的三条推导规则

### 1.1 按值推导：丢弃引用与顶层 `const`

`auto` 默认等价于模板的**按值**形参 `T`，会丢掉引用和顶层 `const` / `volatile`：

```cpp
int x = 10;
const int cx = x;
int& rx = x;

auto a = x;   // int
auto b = cx;  // int（顶层 const 被丢弃）
auto c = rx;  // int（引用被丢弃）—— 注意是 rx，不是 x
```

想保留引用或 `const`，必须显式写出：

```cpp
const auto d = cx;    // const int
auto& e = rx;         // int&
const auto& f = cx;   // const int&
```

### 1.2 数组与函数会退化为指针

按值推导时，数组退化为指向首元素的指针，函数退化为函数指针：

```cpp
int arr[3] = {1, 2, 3};
auto p = arr;        // int*（长度信息丢失）

void func(int);
auto fp = func;      // void(*)(int)
```

> [!tip] 保留数组类型
> 想保住数组长度，用引用：`auto& ra = arr;` → `int(&)[3]`。

### 1.3 花括号初始化列表有特殊规则

```cpp
auto i = {1, 2, 3};   // std::initializer_list<int>
auto j{1};            // C++17：int；C++14：std::initializer_list<int>
auto k = 1, l = 2.5;  // 编译错误：同一句 auto 只能推导出同一种类型
```

> [!warning] 陷阱：`auto` 与代理对象
> ```cpp
> std::vector<bool> v{true, false};
> auto flag = v[0];   // 类型是 std::vector<bool>::reference（代理类，而非 bool）
> ```
> `std::vector<bool>` 做过特化，`v[0]` 返回一个**代理对象**，内部持有指向 vector 存储的指针。`auto flag` 会拷贝这个代理；一旦 vector 被销毁或重新分配，再使用 `flag` 就是**悬空访问**。需要值时应写 `bool flag = v[0];`。

## 二、`auto&&`：万能引用

由引用折叠规则可知，`auto&&` 能同时绑定左值和右值（详见 [[右值引用,移动语义,完美转发|右值引用、移动语义与完美转发]]）：

```cpp
int x = 1;
auto&& a  = x;     // int&（左值引用）
auto&& a1 = 42;    // int&&（右值引用）
auto&& a2 = func();// 由 func 返回值的类别决定
```

> [!note] 说明
> `auto&&` 与模板中的 `T&&` 同为**万能引用**，区别只在"推导源"是 `auto` 还是模板参数。

---

## 三、`decltype`：精确报告类型

`decltype` 不进行"按值退化"，而是报告表达式**确切的类型**：

```cpp
int x = 90;
const int cx = x;
int& rx = x;

decltype(x)    // int
decltype(cx)   // const int
decltype(rx)   // int&
decltype((x))  // int&   ← 注意这里是 (x)，带括号
```

三条规则：

1. `decltype(变量名)`：返回该变量**声明时的类型**（保留引用与 `const`）；
2. `decltype(左值表达式)`（如 `decltype((x))`、`decltype(v[0])`）：返回引用类型 `T&`；
3. `decltype(右值表达式)`（如 `decltype(1 + 1)`、`decltype(f())`）：返回 `T`。

> [!warning] 关键区别：`(x)` 是表达式，不是变量名
> `decltype(x)` 报告变量类型 `int`；`decltype((x))` 中 `(x)` 是一个**左值表达式**，于是结果带上引用，变为 `int&`。多一对括号，结果就变了。

---

## 四、`decltype(auto)`：忠实转发返回值

C++14 引入，专门解决"函数返回值想完美保留类型"的场景——用 `auto` 的写法，套用 `decltype` 的规则：

```cpp
template <typename Container, typename Index>
decltype(auto) get(Container&& c, Index i) {
    return c[i];
}

std::vector<int> v{1, 2, 3};
get(v, 0) = 100;   // 若返回 int& 则合法；若返回 int（临时值）则编译错误
```

这里 `c[i]` 是左值表达式，`decltype(auto)` 推出 `int&`，因此可以赋值。

> [!tip] 三者记忆口诀
> - 局部变量、只关心值 → `auto`；
> - 需要**精确保留类型**（转发、库内部）→ `decltype(auto)`；
> - 只需要**类型名**、不需要值（模板元编程）→ `decltype(expr)`。

## 五、结构化绑定（C++17）

一次解包聚合类型（pair / tuple / 结构体 / 数组）：

```cpp
std::pair<int, std::string> p{1, "hello"};
auto [id, name] = p;   // id = 1, name = "hello"
```

常配合 `if` 的初始化语句使用，把作用域收窄：

```cpp
if (auto it = m.find("key"); it != m.end()) {
    use(it->second);
}
```

> [!note] 拷贝还是引用
> 结构化绑定会引入一个隐藏对象；`auto [a, b] = x` 时它是**拷贝**，`auto& [a, b] = x` 时它才是**引用**。想改动原对象，务必用 `auto&`。

## 六、编译期计算：类型萃取与 `if constexpr`

类型推导不止用于普通变量，也是**模板元编程**的基础。`<type_traits>` 提供了一批编译期可求值的"类型谓词"与类型变换：

| 工具 | 作用 |
| --- | --- |
| `std::is_integral_v<T>` / `std::is_pointer_v<T>` | 编译期判断类型性质 |
| `std::remove_reference_t<T>` / `std::decay_t<T>` | 编译期做类型变换 |
| `std::invoke_result_t<F, Args...>` | 求出"调用 `F` 的返回类型" |
| `std::integral_constant<T, v>` / `std::true_type` | 把值编码进类型，供重载 / 特化选择 |

这些能力配合 `if constexpr`（C++17）就能在**编译期**选择代码路径：

```cpp
template <typename T>
std::string describe(const T& v) {
    if constexpr (std::is_integral_v<T>) {
        return "整数：" + std::to_string(v);
    } else if constexpr (std::is_floating_point_v<T>) {
        return "浮点：" + std::to_string(v);
    } else {
        return "其他类型";
    }
}
```

> [!important] `if constexpr` 的价值
> 与普通 `if` 不同，`if constexpr` 只实例化命中的分支，因此未命中分支里即使存在对当前类型非法的代码也不会报错。这使它比 `SFINAE` 更易读写（见 [[C++深入/C++模板/C++ 函数模板与类型推导|函数模板与类型推导]]）。

> [!tip] 类型 vs 值
> 若需要的是**编译期算出的值**（而非类型），用 `constexpr` 函数 / 变量，详见 [[constexpr编译常量|constexpr 编译期常量]]。

## 七、核心总结

### 7.1 一句话主线

```text
auto          → 按值推导：丢引用、丢顶层 const；数组/函数退化；保留需显式写 &
auto&&        → 万能引用，可同时绑定左值/右值
decltype      → 精确报告：变量名看声明，表达式看值类别（左值加 &）
decltype(auto)→ 用 auto 的写法、套 decltype 的规则，忠实保留返回值类型
结构化绑定    → auto [a,b] = ... 一次性解包（默认拷贝，& 则引用）
编译期计算    → type_traits + if constexpr + constexpr 函数
```

### 7.2 速查表

| 问题 | 答案 |
| --- | --- |
| `auto` 会保留顶层 `const` 吗？ | 不会，`const int` 推出 `int` |
| `auto` 会保留引用吗？ | 不会，`int&` 推出 `int` |
| 数组用 `auto` 会怎样？ | 退化为指针，长度丢失 |
| `auto i = {1,2,3}` 的类型？ | `std::initializer_list<int>` |
| `auto j{1}` 在 C++17 的类型？ | `int`（C++14 为 `initializer_list<int>`） |
| `auto` 遇到 `vector<bool>::reference`？ | 推成代理类型，易悬空，需写 `bool` |
| `decltype(x)` 与 `decltype((x))` 的区别？ | 前者 `int`，后者 `int&`（`(x)` 是左值表达式） |
| `decltype(auto)` 用在哪？ | 完美转发返回值，精确保留类型 |
| 结构化绑定会拷贝吗？ | `auto [a,b]=...` 拷贝；`auto& [a,b]` 引用 |

### 7.3 易错点

- 把 `auto` 当成"原样保留类型"——它默认丢引用、丢顶层 `const`。
- `auto c = rx;` 里若写成 `auto c = x;`，就测不出"引用被丢弃"的效果，要看实际推导结果。
- `auto` + 代理对象（`vector<bool>`、`std::bitset` 等）会得到悬空代理。
- 把 `decltype((x))` 当成 `decltype(x)`——多一对括号结果就带引用。
- 结构化绑定默认是拷贝，想改动原对象要用 `auto&`。
- `if constexpr` 的条件必须是**常量表达式**，不能是运行期条件。
