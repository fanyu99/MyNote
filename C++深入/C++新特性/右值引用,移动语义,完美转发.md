# 右值引用、移动语义与完美转发

承接 [[RAII,资源所有权与unique_ptr|RAII、资源所有权与 unique_ptr]] 中"`std::move` 本身不执行移动"的结论，本篇回答它到底做了什么：先厘清左值与右值的区别，再说明右值引用如何支撑移动语义，最后用**引用折叠**解释完美转发怎样把参数原样交给下一层函数。

> [!important] 核心主线
> **右值引用把"临时对象/即将销毁的对象"标识出来，使资源可以被转移而不是被复制。**
> `std::move` 只做类型转换（不移动任何东西），真正的移动由**移动构造函数 / 移动赋值运算符**完成；`std::forward` 则借助**引用折叠**，在模板中保留参数的左值/右值属性，实现完美转发。

---

## 一、左值与右值

**左值（lvalue）**：有名字、可以取地址。例如变量名、返回左值引用的函数调用。

**右值（rvalue）**：不能取地址、没有名字，一般是**临时对象**或**字面量**，例如 `23`、`3 + 4` 的结果。

| 判别项 | 左值 | 右值 |
|---|---|---|
| 有名字 | 有 | 无 |
| 能否取地址 `&x` | 能 | 不能 |
| 典型例子 | 变量、`++i` | 字面量、`i++`、函数返回的临时对象 |

> [!note] 为什么要区分
> 右值意味着"这个对象很快就不需要了"，因此它的资源可以被**直接掠夺**（移动），而左值代表的对象往往之后还会被使用，只能**复制**。这是移动语义的前提。

---

## 二、右值引用 `&&`

`&&` 在**具体类型**上表示右值引用；在**模板参数推导**中则是万能引用（见第五节）。

```cpp
int&& rref = 23; // 绑定到字面量（一个右值）
```

绑定规则：

- 左值引用 `T&` 只能绑定左值；但 **`const T&` 可以绑定右值**；
- 右值引用 `T&&` 只能绑定右值。

> [!important] 右值引用本身是左值
> 右值引用一旦**有了名字**，它本身就是一个左值。
> 因此在函数内部想继续把参数按右值传递，必须再 `std::move` 一次。

```cpp
void foo(int&& x) {
    bar(x);              // x 是具名变量 → 左值 → 调用 bar(int&)
    bar(std::move(x));   // 转回右值       → 调用 bar(int&&)
}
```

## 三、移动语义与 `std::move`

### 3.1 移动构造与移动赋值

`std::move` 只是"允许移动"，真正执行资源转移的是**移动构造函数**和**移动赋值运算符**。

```cpp
class Buffer {
public:
    Buffer(Buffer&& other) noexcept          // 移动构造
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;               // 关键：置空源对象，避免它析构时释放同一块内存
        other.size_ = 0;
    }

    Buffer& operator=(Buffer&& other) noexcept { // 移动赋值
        if (this != &other) {
            delete[] data_;                  // 先释放自己原有的资源
            data_ = other.data_;
            size_ = other.size_;
            other.data_ = nullptr;
            other.size_ = 0;
        }
        return *this;
    }

private:
    int* data_ = nullptr;
    std::size_t size_ = 0;
};
```

```cpp
Buffer a;
Buffer b = std::move(a); // 调用移动构造：b 接管 a 的资源，a 被置空
```

> [!warning] 移动后源对象处于"有效但未指定"状态
> 移动构造必须把源对象的资源指针**置空**，否则源对象析构时会释放已被转移的资源，造成重复释放。
> 被移动后的对象只能安全地**析构或重新赋值**，不应再假定它保存着原来的值。

### 3.2 `std::move` 的本质

`std::move` 只是一个类型转换，**不会移动任何东西**：

```cpp
// 近似实现：去掉引用后强转为右值引用
template <typename T>
constexpr std::remove_reference_t<T>&& move(T&& t) noexcept {
    return static_cast<std::remove_reference_t<T>&&>(t);
}
```

它把左值"标记"成右值引用，从而在**重载决议**时选中移动构造 / 移动赋值，真正的资源转移发生在那里。

## 四、引用折叠

当类型中出现"引用的引用"（主要由模板参数推导产生）时，编译器按下面的规则折叠：

| 折叠前 | 折叠后 |
|---|---|
| `T& &` | `T&` |
| `T& &&` | `T&` |
| `T&& &` | `T&` |
| `T&& &&` | `T&&` |

> [!important] 规律
> **只要有一个左值引用（`&`），结果就是左值引用；只有两个都是右值引用（`&& &&`）时，结果才是右值引用。**


---

## 五、万能引用（转发引用）

在泛型编程中经常出现万能引用，它能**同时绑定左值和右值**。其成立需要同时满足两个条件：

1. 类型必须来自**模板参数推导**（如 `template<typename T>` 中的 `T`）；
2. 声明形式必须是 `T&&`。

```cpp
template <typename T>
void forwarding(T&& x);            // 万能引用 ✓

template <typename T>
void not_forwarding(const T&& x);  // const 右值引用，不是万能引用 ✗

template <typename T>
void also_not(std::vector<T>&& x); // vector 右值引用，不是万能引用 ✗

// auto&& 也是万能引用（C++11 起）
auto&& universal = some_expression; // 万能引用 ✓
```

> [!warning] `const T&&` 不是万能引用
> 只有"裸"的 `T&&` 才是万能引用。加上 `const`（`const T&&`）或写成具体类型（`std::vector<T>&&`）后，推导出的就只是普通的右值引用，无法再绑定左值。

## 六、完美转发 `std::forward`

完美转发 = 借助**万能引用 + 引用折叠**，把参数**原样**转交给下一个函数，不丢失它的左值 / 右值属性（即：原来能移动的仍然能移动）。

```cpp
template <typename T>
void wrapper(T&& arg) {          // 万能引用（不是右值引用）
    foo(std::forward<T>(arg));   // 根据 T 的推导结果决定是否移动
}

// 传入左值：T 推导为 int&，arg 的类型为 int& && → 折叠为 int&（保持左值）
// 传入右值：T 推导为 int， arg 的类型为 int&&            （保持右值）
```

> [!important] 使用原则
> **只对万能引用使用 `std::forward`。**
> 对普通右值引用变量或具体类型使用 `std::forward` 没有意义；而在需要把参数继续交给下一层时，`std::forward` 才能保住它的值类别。

## 七、核心总结

### 7.1 一句话主线

```text
左值/右值      → 有名字、可取地址的是左值；临时对象/字面量是右值
右值引用 T&&   → 只能绑定右值；但它本身是左值（具名后需再 std::move）
std::move      → 仅做类型转换，不移动任何东西；真正移动靠移动构造/赋值
引用折叠       → 有一个 & 结果就是 &，只有 && && 才折叠为 &&
万能引用       → 模板推导下的 T&&（或 auto&&），可同时绑定左右值
std::forward   → 配合万能引用，保留参数的左值/右值属性实现完美转发
```

### 7.2 速查表

| 问题 | 答案 |
| --- | --- |
| 左值和右值怎么区分？ | 有名字、可取地址的是左值；字面量与临时对象是右值 |
| `T&` 能绑定右值吗？ | 不能；但 `const T&` 可以 |
| `T&&` 能绑定左值吗？ | 不能（模板中推导出的 `T&&` 是万能引用，除外） |
| 右值引用变量本身是左值还是右值？ | 是左值，需要 `std::move` 才能继续按右值传递 |
| `std::move` 会移动对象吗？ | 不会，它只是类型转换，真正的移动由移动构造/赋值完成 |
| 引用折叠的规律是什么？ | 有一个 `&` 结果就是 `&`；只有 `&& &&` 才折叠为 `&&` |
| 什么是万能引用？ | 模板推导下的 `T&&`（以及 `auto&&`），可同时绑定左右值 |
| 什么时候用 `std::forward`？ | 只在万能引用中，用于把参数原样转发给下一层函数 |

### 7.3 易错点

- 引用折叠中 `T&& &&` 折叠为 **`T&&`**（右值引用），只有这一个组合不是左值引用。
- 右值引用变量**本身是左值**——有名字后要再 `std::move` 才能继续当右值传递。
- `std::move` **不移动任何东西**，它只是一个类型转换；别把"调用 `std::move`"当成"已经完成移动"。
- 只有**万能引用**才用 `std::forward`；对普通右值引用或具体类型用它没有意义。
- `const T&&` 与具体类型（如 `std::vector<T>&&`）都**不是**万能引用。
- 移动构造/赋值后要把源对象的资源指针**置空**，否则会造成重复释放。
