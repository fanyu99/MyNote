# 索引优化

## 联合索引的最左前缀法则

### 原理

B+ 树的排序是从左到右的键值进行的排序，`a.k1 = b.k1` 再比较 `a.k2` 和 `b.k2`。那么跳过中间列、运用计算、范围查询（一般）就不会利用 B+ 树天然的有序性，因此不会用索引。

### 规则

1. **必须包含从左到右的列**（无关顺序），不能跳过中间的列，否则其右边的索引会失效（如果跳过最左列，直接全部失效）
2. **范围查询的影响**：如果左边的列使用了范围查询（如 `BETWEEN AND`、`<=>`、`!=`、`IS NOT`、`LIKE` 前缀匹配可能右边的索引依旧生效），但 `IN` 一般作为等值查询，后面的数据使用索引下推（`USING INDEX CONDITION`），其右边的列的索引很可能会失效
3. 范围查询下如果遵循 B+ 树的比较原则，依然可以走索引
4. 查询原则会根据数据的分布进行修改，如果走索引还没有全表扫描快，将使用全表扫描

### 示例

表中有 `(name, age, city)` 联合索引：

| 查询语句 | 索引使用情况 |
|---------|------------|
| `WHERE name=... AND age=... AND city=...` | 使用全部索引 |
| `WHERE name=... AND age=...` | 使用前两个索引 |
| `WHERE age=... AND city=...` | 无法使用索引（缺失最左边的 name 列） |
| `WHERE name=... AND city=...` | 只能使用 name 的索引，city 的索引失效 |
| `WHERE city=... AND age=... AND name=...` | 使用全部索引（与顺序无关，但必须包含从左到右的所有列） |
| `WHERE name=... AND age>18 AND city=...` | 使用前面的 name、age 索引，city 索引失效（age 使用了范围查询） |
| `WHERE name=... ORDER BY age, city` | 索引都会生效，name 为等值查询，且 age、city 的排序遵循 B+ 树的天然排序原则 |

## SQL 提示

1. 数据库会根据性能在多个索引中进行选择
2. 使用 `USE INDEX(indexname)` 指定索引：`SELECT * FROM ... USE INDEX(索引名) ...`
3. 使用 `IGNORE INDEX(indexname)` 忽略索引
4. 使用 `FORCE INDEX(indexname)` 强制索引

## 覆盖索引（Using Index）

仅需使用索引就可返回结果而无需回表查询。

### 模型

- **聚集索引**中 B+ 树叶子节点存储的是每行的数据
- **二级索引**中 B+ 树叶子节点存储的是对应的主键 ID

所以当出现覆盖索引（`USING INDEX`）时，不需要进行回表查询；而未覆盖索引（`USING INDEX CONDITION`）需进行回表查询。

**例如：**

主键为 `id`，联合索引为 `(name, age)`：

```sql
SELECT id, name, age FROM ... WHERE id=... AND name=... AND age=...
-- 存在主键 ID 和联合索引 name_age，对应叶子节点已经包含了要查询的数据，此时无需回表去查询 city
```

### 优势

- 无需回表，减少 IO
- 减少内存的使用
- 减少范围查询对索引的影响，可以优化

## 效率查询的选择原则

1. 针对数据量大且查询频繁的表建立索引（需要控制索引数量）
2. 针对常作为 `WHERE`、`ORDER BY`、`GROUP BY` 的字段建立索引
3. 在创建索引时，尽量将**高区分度**（不同数值数 / 总数）的列放在创建索引的列的前面
4. **等值列 > 范围列 > 排序列 > 分组列**
5. 必须包含从左到右的所有列（可乱序），避免中间断点导致后面的索引失效
6. 使用范围查询的列尽量是原索引的后面的列，避免前面的列使用范围查询成为"断点"
7. 范围查询在后，等值查询在前，代价较小
8. 覆盖索引：例如 `(a, b, c)` → `SELECT b, c ... WHERE a>3 AND b=5 AND c=9`，b、c 覆盖了 a，代价较小
9. `LIKE` 最好使用前缀匹配，代价较小
10. **不要在索引列上进行运算**（后面索引将会失效）
11. 字符串要使用引号（不使用引号存在隐式转换，会让索引失效）
12. `OR` 表达式中左右的列都有索引时才会使用索引
13. 尽量根据表的数据分布进行选择表达式
14. 大量文本内容时使用前缀索引
15. 涉及多个查询条件时优先考虑使用联合索引（很多情况可以作为覆盖索引）

## 前缀索引

在特长字符串 / 大文本数据中，将字符串的部分前缀建立索引，提高索引效率。

```sql
-- 语法：指定列的前 n 个字符作为索引的键
CREATE INDEX ... ON ...(column(n));
```

**前缀的长度**：根据索引的前缀的选择性（区分度）决定，最好平衡前缀区分度和前缀长度。

> **区分度** = 不同索引值 / 数据记录总数

**查询顺序**：在前缀索引中找到匹配的前缀对应的主键 ID 后回表查询数据。
