# 锁

## 1. 全局锁（锁定数据库）

数据库变只读，后续除读以外事务都将被阻塞，用于保证数据一致性。

```sql
FLUSH TABLES WITH READ LOCK;
UNLOCK TABLES;
```

一般用于**全库备份**。

## 2. 表级锁

粒度大，锁冲突概率大，并发量低。

### 1) 表锁

```sql
-- 加锁
LOCK TABLES 表列表 READ/WRITE;

-- 解锁
UNLOCK TABLES;
-- 或客户端断开连接
```

| 类型 | 作用 |
|------|------|
| `READ` | 所有人可读，不可写 |
| `WRITE` | 只有自己可读写，其他都不能读写 |

### 2) 元数据锁（MDL）

为了避免 DML 和 DDL 冲突，保证读写正确性。

在事务中：

| 行为 | 锁类型 |
|------|--------|
| `SELECT` / `INSERT` / `UPDATE` / `DELETE` | MDL 读写锁，与 EXCLUSIVE 互斥 |
| `ALTER` | MDL EXCLUSIVE 锁（阻塞一切），与读写锁互斥 |

### 3) 意向锁

用于减少行锁与表锁的冲突，减少表锁对每行数据的检查。

| 类型 | 含义 |
|------|------|
| `IS` | 意向共享锁，与 READ 兼容，和 WRITE 互斥 |
| `IX` | 意向排他锁，与 READ、WRITE 都互斥；意向锁之间不会互斥 |

## 3. 行级锁

用于锁住对应的行数据，粒度最小，锁冲突概率最低，并发度最高。

### 1) 行锁（Record Lock）

对单个行记录（必须为索引）加锁，防止其他事务对该行进行 `UPDATE` 或 `DELETE`（RC、RR 隔离级别）。

> **注**：不是对索引加锁时，将会升级为表锁。

![行锁](锁_img1.png)

### 2) 间隙锁（Gap Lock）

对索引记录的间隙（开区间）加锁，确保间隙不变，防止在间隙中 `INSERT`。

用于避免**幻读**（PR 隔离级别以下）。

间隙锁可以共存不互斥。

### 3) 临键锁（Next-Key Lock）

同时对行记录及索引间隙加锁（RR 隔离级别以下）。

![临键锁](锁_img2.png)

### 临键锁行为总结

| 索引类型 | 锁行为 |
|---------|--------|
| 唯一索引 | 退化为 Record Lock |
| 普通索引 | Next-Key Lock |
| 无索引 | 全表锁 |
