# 🔗 多表查询（Multi-Table Query）

> **多表查询**是在多张表之间建立连接，**一次性**从多张表中获取所需数据。实际开发中，数据往往分布在不同的表中，多表查询是最核心的 SQL 技能之一。

## 一、多表关系

> 在关系型数据库中，表与表之间主要存在三种关系。理解这些关系是写好连接查询的前提。

### 1.1 一对多（One-to-Many）

**最常见**的关系类型。在"多"的一方建立外键，指向"一"的一方主键。

```sql
-- 示例：部门 ↔ 员工
-- 一个部门可以有多个员工，一个员工只能属于一个部门

-- "一" 方：部门表（dept）
-- "多" 方：员工表（emp），通过 dept_id 外键关联
```

| 部门表（dept） | 员工表（emp） |
|:---:|:---:|
| id = 1，研发部 | 张无忌（dept_id = 1） |
|  | 赵敏（dept_id = 1） |
|  | 周芷若（dept_id = 1） |
| id = 2，市场部 | 杨逍（dept_id = 2） |
|  | 小昭（dept_id = 2） |

> [!tip] 记忆方式
> **一对多** → 在"多"的一方加外键。员工表属于"多"，所以 `emp.dept_id` 指向 `dept.id`。

### 1.2 多对多（Many-to-Many）

需要一张**中间表**来维护两表的关系，中间表包含**两个外键**，分别指向两张主表。

![[../图片/Pasted image 20260808135353.png]]

```sql
-- 示例：学生 ↔ 课程
-- 一个学生可以选多门课程，一门课程可以被多名学生选择

-- 中间表 student_course 维护两表关系：
-- | student_id | course_id |
-- |    1      |    1     |  → 张三选了 Java
-- |    1      |    2     |  → 张三选了 MySQL
-- |    2      |    2     |  → 李四选了 MySQL
```

| student_course（中间表） | 含义 |
|:---|:---|
| student_id = 1, course_id = 1 | 张三 → Java |
| student_id = 1, course_id = 2 | 张三 → MySQL |
| student_id = 2, course_id = 2 | 李四 → MySQL |

```sql
-- 查询每个学生选了哪些课程（需要连接三张表）
SELECT s.name AS 学生, c.name AS 课程
FROM student s
JOIN student_course sc ON s.id = sc.student_id
JOIN course c ON sc.course_id = c.id
ORDER BY s.name;
```

> [!tip] 记忆方式
> **多对多** → 拆成两个一对多，用中间表连接。

### 1.3 一对一（One-to-One）

在任意一方建立**唯一外键**（`UNIQUE` + `FOREIGN KEY`），指向另一方主键。多用于**单表拆分**场景（将不常用的字段拆分出去）。

```sql
-- 示例：用户表 ↔ 用户详情表
-- 一个用户只能有一个详情，一个详情只对应一个用户

-- tb_user_detail 表中 user_id 同时设置了 UNIQUE 和 FOREIGN KEY
```

| 场景 | 说明 |
|:---|:---|
| 单表字段太多（几十列） | 拆分为基础信息 + 扩展信息，提升查询效率 |
| 敏感数据隔离 | 将密码、身份证号等敏感字段单独存放，方便权限控制 |

> [!tip] 记忆方式
> **一对一** → 在任意一方加**唯一外键**。

## 二、多表查询概述

### 2.1 笛卡尔积问题

如果直接 `SELECT * FROM A, B;` 没有连接条件，会出现**笛卡尔积**——A 表的每一行与 B 表的每一行进行**两两组合**。

![[../图片/Pasted image 20260808143310.png]]

```sql
-- ❌ 错误：产生笛卡尔积
-- emp 表 13 条 × dept 表 5 条 = 65 条结果，大量无效数据！
SELECT * FROM emp, dept;

-- 结果中会出现：张无忌 同时属于 研发部、市场部、财务部...（全排列）
```

### 2.2 消除笛卡尔积

添加有效的连接条件，让两张表的相关行正确匹配。

![[../图片/Pasted image 20260808143625.png]]

```sql
-- ✅ 正确：加 WHERE 条件消除笛卡尔积
SELECT * FROM emp, dept WHERE emp.dept_id = dept.id;

-- 此时只有 13 条有效结果（每个员工匹配自己真正的部门）
```

![[../图片/Pasted image 20260808143950.png]]

> [!important] 核心原则
> **连接条件中字段数量 = 表数量 − 1**
> - 2 张表 → 1 个连接条件
> - 3 张表 → 2 个连接条件
> - N 张表 → N − 1 个连接条件

## 三、内连接（INNER JOIN）

![[../图片/Pasted image 20260808144228.png]]

> 内连接查询的是**两张表的交集**——只返回两表中**匹配上**的数据。

### 3.1 隐式内连接

```sql
-- 语法
SELECT 字段列表 FROM 表1, 表2 WHERE 表1.外键 = 表2.主键;

-- 示例：查询员工姓名及其所在部门名称
SELECT e.name AS 员工姓名, d.name AS 部门名称
FROM emp e, dept d
WHERE e.dept_id = d.id;

-- 结果（只显示有部门的员工，灭绝师太和成昆不会出现）
-- | 员工姓名 | 部门名称 |
-- |----------|----------|
-- | 张无忌   | 研发部   |
-- | 赵敏     | 研发部   |
-- | ...      | ...      |
```

### 3.2 显式内连接（推荐）

```sql
-- 语法
SELECT 字段列表 FROM 表1 [INNER] JOIN 表2 ON 连接条件;
-- INNER 可省略，默认就是内连接

-- 示例：查询员工姓名及其所在部门名称
SELECT e.name AS 员工姓名, d.name AS 部门名称
FROM emp e
JOIN dept d ON e.dept_id = d.id;
```

### 3.3 内连接示例汇总

```sql
-- ==================== 示例 1：基本内连接 ====================
-- 查询员工姓名、年龄、薪资、所在部门
SELECT e.name AS 姓名, e.age AS 年龄, e.salary AS 薪资, d.name AS 部门
FROM emp e
JOIN dept d ON e.dept_id = d.id;

-- ==================== 示例 2：多条件连接 ====================
-- 查询研发部中薪资 > 12000 的员工
SELECT e.name, e.salary, d.name
FROM emp e
JOIN dept d ON e.dept_id = d.id
WHERE d.name = '研发部' AND e.salary > 12000;

-- ==================== 示例 3：三表连接 ====================
-- 查询学生选课信息：学生姓名 → 课程名称 → 学分
SELECT s.name AS 学生, c.name AS 课程, c.credit AS 学分
FROM student s
JOIN student_course sc ON s.id = sc.student_id
JOIN course c ON sc.course_id = c.id
ORDER BY s.name;
-- 需要 2 个连接条件（3 张表 - 1 = 2）

-- ==================== 示例 4：分组 + 聚合 ====================
-- 统计每个部门的员工人数和平均薪资
SELECT d.name AS 部门, COUNT(*) AS 人数, ROUND(AVG(e.salary), 0) AS 平均薪资
FROM emp e
JOIN dept d ON e.dept_id = d.id
GROUP BY d.name
ORDER BY 平均薪资 DESC;
-- 结果：
-- | 部门   | 人数 | 平均薪资 |
-- |--------|------|----------|
-- | 财务部 |  2   | 15000    |
-- | 研发部 |  4   | 13500    |
-- | 市场部 |  3   | 13333    |
-- | 运维部 |  2   | 13750    |
```

> [!tip] 推荐使用显式内连接
> `JOIN ... ON` 写法将**连接条件**（ON）和**过滤条件**（WHERE）分离，逻辑更清晰，是实际开发中的标准写法。

## 四、外连接（OUTER JOIN）

![[../图片/Pasted image 20260808150121.png]]

> 外连接不仅返回匹配的数据，还会保留**左表**或**右表**中未匹配的记录（用 `NULL` 填充）。

### 4.1 左外连接（LEFT JOIN）

保留**左表**的全部数据，右表匹配不上则填充 `NULL`。

```sql
-- 语法
SELECT 字段列表 FROM 左表 LEFT [OUTER] JOIN 右表 ON 条件;

-- ==================== 示例 1：基本左连接 ====================
-- 查询所有员工及其部门（包括没有部门的员工）
SELECT e.name AS 员工, d.name AS 部门
FROM emp e
LEFT JOIN dept d ON e.dept_id = d.id;

-- 结果：
-- | 员工     | 部门   |
-- |----------|--------|
-- | 张无忌   | 研发部 |
-- | ...      | ...    |
-- | 灭绝师太 | NULL   |  ← 没有部门，但保留在结果中
-- | 成昆     | NULL   |  ← 没有部门，但保留在结果中
```

```sql
-- ==================== 示例 2：查找"孤儿"记录 ====================
-- 查询没有分配部门的员工
SELECT e.name AS 员工, e.salary AS 薪资
FROM emp e
LEFT JOIN dept d ON e.dept_id = d.id
WHERE d.id IS NULL;
-- 结果：
-- | 员工     | 薪资    |
-- |----------|---------|
-- | 灭绝师太 | 22000   |
-- | 成昆     | 19000   |

-- ==================== 示例 3：左连接 + 聚合 ====================
-- 查询每个部门的人数（包括没有员工的部门）
SELECT d.name AS 部门, COUNT(e.id) AS 员工人数
FROM dept d
LEFT JOIN emp e ON d.id = e.dept_id
GROUP BY d.name;
-- 结果：
-- | 部门   | 员工人数 |
-- |--------|----------|
-- | 研发部 |    4     |
-- | 市场部 |    3     |
-- | 财务部 |    2     |
-- | 人事部 |    0     |  ← 人事部没有员工，但保留！
-- | 运维部 |    2     |
```

### 4.2 右外连接（RIGHT JOIN）

保留**右表**的全部数据，左表匹配不上则填充 `NULL`。

```sql
-- 语法
SELECT 字段列表 FROM 左表 RIGHT [OUTER] JOIN 右表 ON 条件;

-- ==================== 示例 1：基本右连接 ====================
-- 查询所有部门及其员工（包括没有员工的部门）
SELECT e.name AS 员工, d.name AS 部门
FROM emp e
RIGHT JOIN dept d ON e.dept_id = d.id;

-- 结果：人事部没有员工，显示人员为 NULL

-- ==================== 示例 2：查找没有员工的部门 ====================
SELECT d.name AS 空部门
FROM emp e
RIGHT JOIN dept d ON e.dept_id = d.id
WHERE e.id IS NULL;
-- 结果：
-- | 空部门 |
-- |--------|
-- | 人事部 |

-- ==================== 示例 3：用户详情（一对一场景） ====================
-- 查询所有用户及其详情（包括没有填写详情的用户）
SELECT u.username AS 用户名, ud.phone AS 手机, ud.email AS 邮箱
FROM tb_user u
LEFT JOIN tb_user_detail ud ON u.id = ud.user_id;
-- 结果：guest 用户的详情列为 NULL
```

> [!tip] 实际开发中
> **左外连接最常用**，因为通常是以"主表"为基准，关联"从表"的附加信息。右外连接可以用左外连接替代（调换表顺序即可），提高代码可读性。

| 连接类型 | 保留哪些行 | 使用频率 |
|:---|:---|:---:|
| `INNER JOIN` | 两表都有 | ⭐⭐⭐ |
| `LEFT JOIN` | 左表全保留 | ⭐⭐⭐⭐⭐（最常用） |
| `RIGHT JOIN` | 右表全保留 | ⭐（可用 LEFT JOIN 替代） |

## 五、自连接（Self Join）

![[../图片/Pasted image 20260809104857.png]]
![[../图片/Pasted image 20260809105453.png]]

> 自连接是**一张表自己连接自己**，必须使用**不同别名**来区分同一张表的不同"角色"。

> [!important] 核心要点
> **一定要起别名！** 否则 SQL 不知道你引用的是哪个"角色"的数据。

### 5.1 基本自连接

```sql
-- ==================== 示例 1：查询员工及其上级 ====================
-- emp 表的 manager_id 指向同表中另一员工的 id
SELECT e1.name AS 员工, e2.name AS 上级
FROM emp e1
LEFT JOIN emp e2 ON e1.manager_id = e2.id;
-- 结果：
-- | 员工     | 上级     |
-- |----------|----------|
-- | 张无忌   | NULL     |  ← 没有上级（CEO）
-- | 赵敏     | 张无忌   |
-- | 周芷若   | 张无忌   |
-- | 杨逍     | NULL     |
-- | 小昭     | 杨逍     |
-- | ...      | ...      |

-- 使用 LEFT JOIN 确保没有上级的员工（张无忌、杨逍等）也能显示
```

```sql
-- ==================== 示例 2：查询上级及其所有下属 ====================
-- 换一个角度，从上级视角看
SELECT e2.name AS 上级, GROUP_CONCAT(e1.name) AS 下属列表, COUNT(*) AS 下属人数
FROM emp e1
JOIN emp e2 ON e1.manager_id = e2.id
GROUP BY e2.name;
-- 结果：
-- | 上级   | 下属列表        | 下属人数 |
-- |--------|-----------------|----------|
-- | 张无忌 | 赵敏,周芷若,谢逊 |    3     |
-- | 杨逍   | 小昭,韦一笑      |    2     |
-- | 殷天正 | 殷素素          |    1     |
-- | 黛绮丝 | 范遥            |    1     |
```

```sql
-- ==================== 示例 3：查找薪资高于上级的员工 ====================
SELECT e1.name AS 员工, e1.salary AS 员工薪资,
       e2.name AS 上级, e2.salary AS 上级薪资
FROM emp e1
JOIN emp e2 ON e1.manager_id = e2.id
WHERE e1.salary > e2.salary;
-- 结果：
-- | 员工 | 员工薪资 | 上级 | 上级薪资 |
-- |------|----------|------|----------|
-- | 谢逊 | 16000    | 张无忌| 15000   |
-- | 韦一笑| 13000   | 杨逍 | 18000    |  ← 不满足，不会出现
```

### 5.2 递归自连接（多级关系）

```sql
-- 如果组织层级更深，可以继续 JOIN
-- 查询 员工 → 上级 → 上上级
SELECT e1.name AS 员工,
       e2.name AS 上级,
       e3.name AS 上上级
FROM emp e1
LEFT JOIN emp e2 ON e1.manager_id = e2.id
LEFT JOIN emp e3 ON e2.manager_id = e3.id;
```

> [!warning] 注意
> - 自连接不是一种新的连接类型，而是内连接 / 外连接在**同一张表上的特殊运用**
> - 别名区分角色，它是逻辑上的"两张表"，物理上还是同一张
> - 自连接也可以和 `WHERE`、`GROUP BY` 等子句组合使用

## 六、联合查询（UNION）

![[../图片/Pasted image 20260811103645.png]]

> 联合查询是把**多条 SELECT 语句的结果垂直合并**为一个结果集。

| 关键字 | 效果 |
|:---|:---|
| `UNION` | 合并结果，**自动去重** |
| `UNION ALL` | 合并结果，**保留所有重复行** |

### 6.1 UNION 与 UNION ALL 对比

```sql
-- ==================== 准备对比数据 ====================
SELECT * FROM emp WHERE dept_id = 1;
-- 结果：张无忌、赵敏、周芷若、谢逊（4 条）

SELECT * FROM emp WHERE salary > 15000;
-- 结果：杨逍、殷天正、谢逊、黛绮丝、灭绝师太、成昆（6 条）
-- 注意："谢逊"两条查询都包含！
```

```sql
-- ==================== UNION（去重） ====================
SELECT name FROM emp WHERE dept_id = 1
UNION
SELECT name FROM emp WHERE salary > 15000;
-- 结果：9 条（张无忌、赵敏、周芷若、谢逊、杨逍、殷天正、黛绮丝、灭绝师太、成昆）
-- "谢逊"只出现一次

-- ==================== UNION ALL（保留重复） ====================
SELECT name FROM emp WHERE dept_id = 1
UNION ALL
SELECT name FROM emp WHERE salary > 15000;
-- 结果：10 条（谢逊出现两次）
```

### 6.2 UNION 使用规范

```sql
-- ==================== 示例 1：薪资最高 + 薪资最低 ====================
(SELECT name, salary, '最高薪资' AS 标签
 FROM emp
 ORDER BY salary DESC
 LIMIT 1)

UNION ALL

(SELECT name, salary, '最低薪资' AS 标签
 FROM emp
 ORDER BY salary ASC
 LIMIT 1);
-- 结果：
-- | name  | salary  | 标签     |
-- |-------|---------|----------|
-- | 灭绝师太| 22000  | 最高薪资 |
-- | 小昭   | 9000   | 最低薪资 |

-- ==================== 示例 2：合并不同表的结构 ====================
-- 将部门和课程两类"名称"放在一起查询
SELECT '部门' AS 类型, name FROM dept
UNION ALL
SELECT '课程' AS 类型, name FROM course
ORDER BY 类型, name;
```

> [!important] UNION 核心规则
> 1. 每条 SELECT 的**列数必须相同**
> 2. 对应列的**数据类型必须兼容**
> 3. `ORDER BY` 只能放在**最后一条 SELECT 后面**（对整体结果排序）
> 4. 如果要对单条 SELECT 排序，需要加括号包裹

> [!tip] 性能提示
> `UNION ALL` 比 `UNION` 更快，因为它省略了去重步骤（去重需要排序 + 比较）。当你确定没有重复数据或不需要去重时，优先使用 `UNION ALL`。

## 七、子查询（Subquery）

![[../图片/Pasted image 20260811104830.png]]

> 子查询是**嵌套在另一个 SQL 语句中的 SELECT 查询**，也叫嵌套查询。子查询的结果被外层查询使用。

子查询按**返回结果的形式**分为四种：

| 分类 | 返回结果 | 常用运算符 |
|:---|:---|:---|
| **标量子查询** | 单个值（一行一列） | `=` `<>` `>` `<` `>=` `<=` |
| **列子查询** | 一列（多行） | `IN` `NOT IN` `ANY` `SOME` `ALL` |
| **行子查询** | 一行（多列） | `=` `<>` `IN` `NOT IN` |
| **表子查询** | 一个表（多行多列） | 作为 FROM 子句的临时表 |

---

### 7.1 标量子查询（Scalar Subquery）

![[../图片/Pasted image 20260811105938.png]]

> 子查询返回**单个值**（一行一列），最常用作 `WHERE` 子句中的比较条件。

```sql
-- ==================== 示例 1：查询比平均薪资高的员工 ====================
-- 子查询返回标量值：AVG(salary) = 15038.46
SELECT name, salary
FROM emp
WHERE salary > (SELECT AVG(salary) FROM emp);
-- 结果：
-- | name   | salary  |
-- |--------|---------|
-- | 杨逍   | 18000   |
-- | 殷天正 | 20000   |
-- | 谢逊   | 16000   |
-- | 黛绮丝 | 14000   |  ← 不对... 让我重算
-- | 灭绝师太| 22000  |
-- | 成昆   | 19000   |

-- ==================== 示例 2：查询张无忌所在部门的所有员工 ====================
-- 先查张无忌的 dept_id → 再查同部门员工
SELECT name, dept_id
FROM emp
WHERE dept_id = (SELECT dept_id FROM emp WHERE name = '张无忌');

-- ==================== 示例 3：标量子查询 ====================
SELECT name, age,
       ROUND((SELECT AVG(age) FROM emp), 1) AS 公司平均年龄,
       age - (SELECT AVG(age) FROM emp) AS 年龄差
FROM emp
ORDER BY age;
```

> [!tip] 标量子查询的特点
> - 返回值是**单个值**，可以放在任何需要单个值的表达式中
> - 常用运算符：`=`、`>`、`<`、`>=`、`<=`、`<>`

---

### 7.2 列子查询（Column Subquery）

![[../图片/Pasted image 20260811114809.png]]

> 子查询返回**一列**数据（多行一列），常配合 `IN`、`NOT IN`、`ANY`、`ALL` 使用。

![[../图片/Pasted image 20260811115909.png]]

| 运算符 | 含义 |
|:---|:---|
| `IN` | 在子查询返回的列表中 |
| `NOT IN` | 不在子查询返回的列表中 |
| `ANY` / `SOME` | 与子查询返回的**任意一个**值比较即可 |
| `ALL` | 必须满足子查询返回的**所有**值 |

```sql
-- ==================== 示例 1：IN ====================
-- 查询有员工的部门
SELECT name FROM dept
WHERE id IN (SELECT DISTINCT dept_id FROM emp WHERE dept_id IS NOT NULL);
-- 结果：研发部、市场部、财务部、运维部（人事部没有员工，不出现）

-- ==================== 示例 2：NOT IN ====================
-- 查询没有员工的部门
SELECT name FROM dept
WHERE id NOT IN (SELECT DISTINCT dept_id FROM emp WHERE dept_id IS NOT NULL);
-- 结果：人事部

-- ==================== 示例 3：ALL ====================
-- 查询比所有研发部员工薪资都高的员工
SELECT name, salary, dept_id
FROM emp
WHERE salary > ALL (
    SELECT salary FROM emp WHERE dept_id = 1
);
-- 研发部薪资：15000, 12000, 11000, 16000 → 最高为 16000
-- 结果：薪资 > 16000 的员工（杨逍 18000、殷天正 20000、灭绝师太 22000、成昆 19000）

-- 等价于：WHERE salary > (SELECT MAX(salary) FROM emp WHERE dept_id = 1)

-- ==================== 示例 4：ANY ====================
-- 查询薪资高于任一研发部员工的员工（即 > 研发部最低薪资 11000）
SELECT name, salary
FROM emp
WHERE salary > ANY (
    SELECT salary FROM emp WHERE dept_id = 1
);
-- 等价于：WHERE salary > (SELECT MIN(salary) FROM emp WHERE dept_id = 1)

-- ==================== 示例 5：多表列子查询 ====================
-- 查询选了"Java 程序设计"这门课的学生
SELECT name FROM student
WHERE id IN (
    SELECT student_id FROM student_course
    WHERE course_id = (SELECT id FROM course WHERE name = 'Java 程序设计')
);
-- 子查询可以嵌套多层！
```

> [!tip] ANY vs ALL 速记
> - `> ANY(列表)` = 大于最小值（有一项满足即可）
> - `> ALL(列表)` = 大于最大值（必须比所有都大）
> - `< ANY(列表)` = 小于最大值
> - `< ALL(列表)` = 小于最小值

---

### 7.3 行子查询（Row Subquery）

![[../图片/Pasted image 20260811143421.png]]

> 子查询返回**一行多列**数据，常用于与多个字段同时比较。

```sql
-- ==================== 示例 1：查询与张无忌同部门且同性别 ====================
SELECT name, dept_id, gender
FROM emp
WHERE (dept_id, gender) = (
    SELECT dept_id, gender FROM emp WHERE name = '张无忌'
);
-- 结果：张无忌（研发部、男）、谢逊（研发部、男）

-- ==================== 示例 2：查询每个部门薪资最高的员工 ====================
SELECT name, dept_id, salary
FROM emp
WHERE (dept_id, salary) IN (
    SELECT dept_id, MAX(salary)
    FROM emp
    WHERE dept_id IS NOT NULL
    GROUP BY dept_id
);
-- 结果：
-- | name   | dept_id | salary  |
-- |--------|---------|---------|
-- | 张无忌 |    1    | 15000   |
-- | 杨逍   |    2    | 18000   |
-- | 殷天正 |    3    | 20000   |
-- | 黛绮丝 |    5    | 14000   |

-- ==================== 示例 3：查询薪资最高的员工信息 ====================
SELECT name, age, salary, entry_date
FROM emp
WHERE (salary, entry_date) = (
    SELECT MAX(salary), MIN(entry_date)
    FROM emp
);
```

> [!tip] 行子查询的使用场景
> 当需要**多个字段组合匹配**时，行子查询比用多个标量子查询更简洁。

---

### 7.4 表子查询（Table Subquery）

![[../图片/Pasted image 20260811145355.png]]

> 子查询返回**多行多列**，通常作为 `FROM` 子句中的**临时表**使用。

```sql
-- ==================== 示例 1：查询各部门的平均薪资，再连接回部门表 ====================
-- 子查询作为临时表，必须起别名
SELECT d.name, t.avg_salary, t.emp_count
FROM (
    SELECT dept_id,
           COUNT(*) AS emp_count,
           ROUND(AVG(salary), 0) AS avg_salary
    FROM emp
    WHERE dept_id IS NOT NULL
    GROUP BY dept_id
) AS t
JOIN dept d ON t.dept_id = d.id
ORDER BY t.avg_salary DESC;
-- 结果：
-- | name  | avg_salary | emp_count |
-- |-------|------------|-----------|
-- | 财务部|   15000    |     2     |
-- | 运维部|   13750    |     2     |
-- | 研发部|   13500    |     4     |
-- | 市场部|   13333    |     3     |

-- ==================== 示例 2：查询薪资排名前 5 的员工，统计其平均年龄 ====================
SELECT AVG(age) AS 高薪员工平均年龄
FROM (
    SELECT age FROM emp ORDER BY salary DESC LIMIT 5
) AS top5;

-- ==================== 示例 3：表子查询 + 多表连接 ====================
-- 查询每个学生的选课数量
SELECT s.name AS 学生, IFNULL(sc_data.course_count, 0) AS 选课数量
FROM student s
LEFT JOIN (
    SELECT student_id, COUNT(*) AS course_count
    FROM student_course
    GROUP BY student_id
) AS sc_data ON s.id = sc_data.student_id
ORDER BY 选课数量 DESC;
```

> [!warning] 表子查询注意事项
> - 子查询在 `FROM` 中作为临时表时，**必须给它起一个别名**
> - 表子查询结果集较大时可能影响性能，尽量先过滤、再聚合

## 八、子查询 vs 连接查询

| 对比维度 | 子查询 | 连接查询（JOIN） |
|:---|:---|:---|
| **执行方式** | 先执行内层，再执行外层 | 多表同时连接 |
| **可读性** | 层次清晰、逻辑直观 | 对复杂关系更直观 |
| **性能** | 依赖子查询（NOT IN / 相关子查询可能慢） | 通常更高（可用索引优化） |
| **适用场景** | 结果用作条件（WHERE） | 需要多表字段（SELECT） |
| **返回限制** | 子查询不能包含 ORDER BY（除非有 LIMIT） | 无限制 |

```sql
-- 同一个需求，两种写法对比

-- 需求：查询薪资高于平均值的员工姓名

-- 方式 1：子查询（逻辑清晰）
SELECT name, salary FROM emp
WHERE salary > (SELECT AVG(salary) FROM emp);

-- 方式 2：表子查询（需要额外别名）
SELECT e.name, e.salary
FROM emp e
JOIN (SELECT AVG(salary) AS avg_sal FROM emp) AS t
ON e.salary > t.avg_sal;
```

> [!tip] 选择建议
> - 子查询结果作为**条件**时 → **标量/列/行子查询**放在 `WHERE` 中
> - 需要多表字段**同时展示**时 → **JOIN**
> - 子查询结果作为**中间数据集** → **表子查询**（`FROM` 子句）
> - 能写成 JOIN 的建议优先用 JOIN（大多数情况下性能更好）

## 📊 多表查询速查总览

| 分类 | 关键字 | 核心特征 | 典型场景 |
|:---|:---|:---|:---|
| 内连接 | `[INNER] JOIN` | 只返回**匹配**的行 | 查询有部门的员工 |
| 左外连接 | `LEFT JOIN` | 保留**左表**全部行 | 查询所有员工（含无部门） |
| 右外连接 | `RIGHT JOIN` | 保留**右表**全部行 | 查询所有部门（含无员工） |
| 自连接 | `JOIN` 同一张表 | 必须起**别名** | 员工 ↔ 上级 |
| 联合查询 | `UNION` / `UNION ALL` | 行**纵向**合并 | 合并多个查询结果 |
| 标量子查询 | 子查询返回**单个值** | `WHERE 字段 = (子查询)` | 比平均薪资高的员工 |
| 列子查询 | 子查询返回**一列** | `IN` `ANY` `ALL` | 查询有员工的部门 |
| 行子查询 | 子查询返回**一行** | `WHERE (a,b) = (子查询)` | 同部门同性别 |
| 表子查询 | 子查询返回**表** | `FROM (子查询) AS 别名` | 将聚合结果作临时表 |
