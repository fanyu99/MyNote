# 编码标准与编码器

> **概述**：编码标准是「规则」，编码器是「执行规则的程序」。

## 一、标准、编码器与实现

| 概念 | 例子 | 说明 |
| --- | --- | --- |
| 编码标准 | H.264、H.265/HEVC、AV1、VP9 | 规定压缩数据长什么样的规范 |
| 编码器实现 | `libx264`、`h264_nvenc`、`libx265` | 按标准把原始画面压成码流的程序 |
| 解码器实现 | `h264_cuvid`、内置 H.264 解码器 | 把码流还原成原始画面 |

- 同一个标准可以有多个实现：软件实现（`libx264`）和硬件实现（`h264_nvenc`、`h264_qsv`、`h264_videotoolbox`）。
- 不同实现产出的都是同一种标准码流，但速度、画质、体积不同。
- `codec` = **coder + decoder**，中文常译作「编解码器」，需要根据上下文判断指的是标准还是实现。

## 二、常见视频编码标准

| 标准 | 别名 | 特点 | ffmpeg 编码器 |
| --- | --- | --- | --- |
| **H.264** | AVC | 兼容性最好，绝大多数设备支持 | `libx264`、`h264_nvenc`、`h264_qsv` |
| **H.265** | HEVC | 同画质约省 30% ~ 50% 码率，专利较复杂 | `libx265`、`hevc_nvenc`、`hevc_qsv` |
| VP9 | — | 开源、免授权费，YouTube/WebM 常用 | `libvpx-vp9` |
| **AV1** | — | 开源、压缩率高，软件编码较慢 | `libaom-av1`、`libsvtav1`、`librav1e` |
| H.266 | VVC | H.265 的后续标准，压缩率更高，生态尚不成熟 | 常用构建未必包含 |
| MPEG-2 | — | 老标准，DVD、广播 | `mpeg2video` |
| MPEG-4 Part 2 | DivX / Xvid | 老网络视频 | `mpeg4` |
| ProRes | — | Apple 剪辑中间格式，高码率、易编辑 | `prores` |
| DNxHD / DNxHR | — | Avid 剪辑中间格式 | `dnxhd` |

> [!tip] 怎么选
> - 追求兼容性：**H.264**。
> - 追求更小体积、目标设备支持 HEVC：**H.265**。
> - 网页/开源生态：**VP9 / AV1**。
> - 剪辑中间格式：**ProRes / DNxHD**，不要用 H.264 反复剪辑再导出。

> [!note] 音频编码标准
> AAC、Opus、MP3、FLAC、ALAC 等音频编码器见 [[音频基础#五、常见音频编码器]]。

## 三、编码器命名规律

| 前缀/后缀 | 含义 | 例子 |
| --- | --- | --- |
| `lib*` | 软件编码器 | `libx264`、`libx265`、`libvpx-vp9`、`libsvtav1` |
| `*_nvenc` | NVIDIA 硬件编码 | `h264_nvenc`、`hevc_nvenc` |
| `*_qsv` | Intel Quick Sync | `h264_qsv`、`hevc_qsv` |
| `*_amf` | AMD | `h264_amf`、`hevc_amf` |
| `*_videotoolbox` | macOS | `h264_videotoolbox` |
| `*_vaapi` | Linux | `h264_vaapi` |
| `*_cuvid` | NVIDIA 硬件解码 | `h264_cuvid` |

> [!note] 本机支持哪些编码器
> 不同构建、不同显卡支持的编码器不同；查看命令见 [[命令实操#十、硬件加速]]。

## 四、Profile 与 Level

**Profile** 规定编码器可以使用哪些工具子集；**Level** 规定分辨率、帧率、码率的上限。

| H.264 Profile | 特点 | 常见用途 |
| --- | --- | --- |
| Baseline | 不支持 B 帧，低延迟 | 老设备、视频会议 |
| Main | 支持 B 帧 | 早期广播 |
| **High** | 8bit 4:2:0，压缩效率高 | **最常用** |
| High 10 | 10bit 4:2:0 | 10bit 视频 |
| High 4:2:2 / 4:4:4 | 专业色度采样 | 后期、无损 |

| Level | 大致能力 |
| --- | --- |
| 4.1 | 1080p30 |
| 4.2 | 1080p60 |
| 5.1 | 4K30 |
| 5.2 | 4K60 |

> [!tip] 兼容性优先级
> 不确定目标设备时，选 **H.264 High Profile + Level 4.1 + yuv420p + AAC**，覆盖面最广。HEVC/AV1 压缩率更高，但老设备和部分浏览器支持不完整。

具体命令见 [[命令实操#四、转码与压缩]]。

## 五、编码器参数

| 参数 | 作用 | 经验 |
| --- | --- | --- |
| `-preset` | 编码速度与压缩率的权衡 | `ultrafast` → `veryslow`；默认 `medium`；离线用 `slow`，实时用 `veryfast` |
| `-tune` | 针对内容类型微调 | `film`、`animation`、`grain`、`stillimage`、`fastdecode`、`zerolatency` |
| `-crf` | 恒定质量 | 离线转码首选 |
| `-b:v` | 目标视频码率 | 流媒体、固定带宽 |
| `-maxrate` / `-bufsize` | 峰值码率与缓冲区 | 配合 `-b:v` 或 `-crf` 限制峰值 |
| `-g` | GOP 长度 | 直播 1 ~ 2 秒 |
| `-bf` | B 帧数量 | 低延迟设为 0 |
| `-refs` | 参考帧数量 | 越高压缩率越好，但解码成本更高 |
| `-x264-params` / `-x265-params` | 透传编码器高级参数 | 需要查对应编码器文档 |

> [!note] preset 的收益递减
> `preset` 从 `medium` 往 `veryslow` 走，压缩率提升越来越小、耗时越来越长。离线批量转码可以接受慢一点；直播和实时场景优先 `veryfast` 或硬件编码。

## 六、硬件编码

| 平台 | 常见编码器 |
| --- | --- |
| NVIDIA | `h264_nvenc`、`hevc_nvenc`、`av1_nvenc` |
| Intel | `h264_qsv`、`hevc_qsv`、`av1_qsv` |
| AMD | `h264_amf`、`hevc_amf`、`av1_amf` |
| macOS | `h264_videotoolbox`、`hevc_videotoolbox` |
| Linux | `h264_vaapi`、`hevc_vaapi` |

> [!warning] 硬件编码不是白送的
> 硬件编码速度快、CPU 占用低，但**同码率下画质通常不如软件编码**，且 CRF 语义不一定一致（NVENC 常用 `-cq`，QSV 常用 `-global_quality`）。直播、批量转码优先硬件；追求体积/画质优先 `libx264` / `libx265`。

## 七、如何衡量画质

| 指标 | 说明 |
| --- | --- |
| 主观观感 | 最终标准，看暗部、运动、文字边缘 |
| PSNR | 峰值信噪比，越高越好，但与主观感受相关性一般 |
| SSIM | 结构相似性，比 PSNR 更接近人眼 |
| VMAF | Netflix 提出，综合多个特征，目前较常用；需要 `libvmaf` |

> [!note] CRF 不是跨编码器的质量单位
> CRF 只是某个编码器的内部质量目标。比较不同编码器时，应该固定码率或固定 VMAF，再比较体积/画质，而不是直接比较 CRF 数值。

VMAF 对比命令见 [[命令实操#四、转码与压缩]]。

## 八、小结

- **标准是规则，编码器是实现**；同一个标准可以有软件和硬件多种实现。
- H.264 兼容性最好；H.265 更省码率；VP9/AV1 面向开源与网页；ProRes/DNxHD 用于剪辑中间格式。
- 编码器命名看前后缀：`lib*` 软件，`*_nvenc`/`*_qsv`/`*_amf`/`*_videotoolbox`/`*_vaapi` 硬件。
- H.264 常用 **High Profile + Level 4.1**；不确定设备能力时优先兼容性。
- `preset` 控制速度/压缩率，`tune` 针对内容类型，`crf` 控制质量，`-b:v` 控制码率。
- 硬件编码快但同码率画质通常不如软件；画质可用 PSNR/SSIM/VMAF 辅助评估。
