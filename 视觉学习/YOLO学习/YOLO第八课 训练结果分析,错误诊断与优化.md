## 1. 验证指标解读

以 African Wildlife 数据集（4 类：buffalo / elephant / rhino / zebra）正式训练 50 轮后的验证结果为例：

| 类别 | 图片数 | 目标数 | Precision | Recall | mAP50 | mAP50-95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| **all** | 225 | 379 | **0.944** | **0.924** | **0.969** | **0.831** |
| buffalo | 62 | 89 | 0.953 | 0.910 | 0.964 | 0.849 |
| elephant | 53 | 91 | 0.899 | **0.934** | **0.974** | 0.826 |
| rhino | 55 | 85 | **0.966** | 0.929 | 0.972 | **0.863** |
| zebra | 59 | 114 | 0.957 | 0.921 | 0.968 | 0.785 |

各指标含义：

- `Precision`（查准率）：检测出来的目标里，**有多少是真正正确的**；
- `Recall`（查全率）：真实存在的目标里，**有多少被找到了**；
- `mAP50`：在 IoU = 50% 标准下测得的 mAP；
- `mAP50-95`：在 IoU = 50%~95% 的多个标准下测得 mAP 后再取平均，**对定位精度更严格**。

> [!tip] `mAP50` 高而 `mAP50-95` 低说明什么
> 说明模型"认得出、但框不准"——分类没问题，边界框回归精度不够。指标定义见 [[YOLO第二课 IoU、Precision、Recall、AP、mAP|第二课]]。

### 训练日志里的三个损失

YOLO26 训练进度条上会打印三个损失：

| 损失 | 含义 |
| --- | --- |
| `box_loss` | 边界框定位损失（基于 IoU 的回归误差） |
| `cls_loss` | 分类损失，衡量类别判断的误差 |
| `l1_loss` | 边界框回归的 L1 误差 |

> [!note] 为什么是 `l1_loss`，不是 `dfl_loss`
> YOLOv8 时代第三项是 `dfl_loss`（分布焦点损失）；**YOLO26 为了做端到端输出移除了 DFL**，边界框回归改为直接用 L1 误差，所以损失名变成 `l1_loss`。DFL 的原理见 [[YOLO第四课 检测输出、边界框解码与NMS|第四课]]。

## 2. 混淆矩阵

![[confusion_matrix.png|580]]

> [!warning] 先看清方向：**行 = 预测（Predicted），列 = 真实（True）**
> Ultralytics 的混淆矩阵满足 `matrix[预测类别, 真实类别]`，图上也会分别标注行轴 `Predicted`、列轴 `True`，读图时不要弄反：
> - **最后一列 `background`**：真实是背景，却被预测成了某个类 → **误检（FP）**
> - **最后一行 `background`**：真实有目标，却被判成了背景 → **漏检（FN）**

读图示例：

- `zebra` **行**：对角线 `133` 表示 133 个预测框正确命中真实 zebra；但该行最右侧 `background` 列是 **24**，表示**有 24 处背景被误判成了 zebra** → 明显的**误检**；
- `zebra` **列**：最下方 `background` 行是 **2**，表示**有 2 个真实的 zebra 被漏掉**（判成了背景）→ 明显的**漏检**；
- `elephant` 行与 `rhino` 列的交叉是 **1**，表示**有 1 个真实的 rhino 被误判成了 elephant** → 类别混淆。

> [!tip] 怎么用混淆矩阵改进
> 哪一**列**（真实类）下方非对角线格子大，就去补这个类的**易混淆样本**；哪一**行**（预测类）在 `background` 列的值大，就去补这个类的**硬负样本**。

## 3. PR 曲线

![[BoxPR_curve.png|579]]

横轴为 Recall，纵轴为 Precision。曲线整体十分靠近右上角（P → 1.0、R → 1.0），说明模型在很高的 Recall 下仍能保持较高的 Precision，整体检测能力较好。

## 4. F1 曲线

### `F1` 是什么？

$$
F1 = \frac{2PR}{P+R}
$$

即 F1 为 P 与 R 的**调和平均**，越接近 1 越好。它比算术平均更强调两者的**均衡**。

> [!warning] 偏科即挂
> 只要 Precision 或 Recall 有一项很低，F1 就会被明显拉低。所以 F1 能同时反映"误检多不多"和"漏检多不多"。

### 怎么读 F1 曲线

![[BoxF1_curve.png]]

横坐标为 `Confidence` 阈值：对每一个候选阈值，先保留置信度高于该阈值的预测框，再据此计算该阈值下的 Precision、Recall 与 F1。

曲线最高点对应的阈值，就是"P 与 R 最均衡"的推理阈值，可以据此灵活选择 `conf`。

> [!note] 注意
> F1 曲线求出的只是"在某一份验证数据上 P、R 最均衡"的阈值。实际部署时还要根据业务更看重**误检**还是**漏检**，在此基础上再做微调。

## 5. 推理常见问题诊断

### 1. 高置信度语义误检

常见的产生原因：**数据集类别较少 / 训练量少 / 训练集较简单单一 / 训练集漏标**。

有效的解决方式：

- 增加**硬负样本（Hard Negative）**：看起来非常像目标类别，但实际并不是目标类别的内容；
- 检查训练集是否漏标；
- 提高训练集背景的复杂性与多样性。

例如：一张图里检测犀牛，却把旁边的猎豹（可能根本不属于任何类别）当成了犀牛，就造成了高置信度语义误检。解决办法是把"该事物与犀牛同时出现"的图片加入训练集，并明确只标出犀牛。

> [!tip] 为什么不直接新增一个"猎豹"类别
> 除非确实需要单独识别它，否则新增类别会带来新的类别不平衡与标注成本。更常见的做法是把它当作**负样本背景**，让模型学会"它不是犀牛"。

### 2. 低置信度漏检

- 现象：目标确实存在、也有候选框，但置信度较低，未达到 `conf` 而被剔除；
- 常见原因：目标被严重遮挡 / 目标太小太远 / 训练集中同类情况较少。

优化方法：

- 增加遮挡样本；
- 保持标注规则一致，例如"可见面积超过一定比例才标注"；
- 暂时调低 `conf` 收集困难样本，人工判断后再针对性优化。

### 3. 较多同类目标漏检

常见的产生原因：

- **`conf` 阈值设置过高**：置信度偏低但真实存在的目标被剔除；
- **`iou` 设置过低**：NMS 阶段过于激进，靠得近的同类真实目标被当成重复框抑制掉。

> [!warning] `iou` 越低 = 删得越狠
> NMS 的 `iou` 阈值越低，去重越激进、最终留下的框越少，越容易把相邻的同类真实目标误删。

## 6. 各类现象的调整方向

| 现象               | 首先修改           | 调整方向                                 | 可能的副作用      |
| ---------------- | -------------- | ------------------------------------ | ----------- |
| 很多真实目标有框，但置信度较低  | `conf`         | 降低                                   | 误检增加        |
| 误检框置信度很低         | `conf`         | 提高                                   | 漏检增加        |
| 误检框置信度很高         | 训练数据           | 增加硬负样本                               | 需要重新训练      |
| 高度重叠的同类目标只剩一个    | `iou`          | 提高到 `0.7～0.8`                        | 重复框增加       |
| 同一个目标出现多个重复框     | `iou`          | 降低到 `0.5～0.6`                        | 重叠真实目标可能被抑制 |
| 小目标、远处目标漏检       | `imgsz`        | 提高分辨率到 `960/1280`                    | 显存和推理时间增加   |
| 遮挡目标漏检           | 数据集            | 增加遮挡样本                               | 需要采集和标注     |
| 拥挤场景漏检           | 数据集、`iou`      | 增加拥挤样本，适当提高 `iou`                    | 可能增加重复框     |
| 模型整体特征提取能力不足     | 模型尺寸           | `yolo26n` 换成 `yolo26s`               | 速度变慢、显存增加   |
| 单图目标数超过输出上限      | `max_det`      | 提高                                   | 后处理开销增加     |
| 想尝试更稳健的推理        | `augment=True` | 开启 TTA                               | 推理明显变慢      |
| 分类混淆             | 训练集            | 根据混淆矩阵，增加易混淆的边界样本                    | 数据集量变大      |
| 定位框不准确           | 标注规范、丰富目标      | 统一标注规范，丰富目标类型/尺寸/形状，必要时提高分辨率或模型容量    | 处理更加复杂      |
| 领域偏移（不同场景表现差异明显） | 训练集            | 增加不同环境的数据；增加合理的数据增强（例如饱和度/平移/Mosaic） | 需要采集真实数据    |

## 7. 总体优化思路：推理错误驱动训练优化

```
推理测试
   ↓
收集错误案例
   ↓
判断错误类型
   ↓
检查标注和数据分布
   ↓
补充针对性训练数据
   ↓
必要时调整数据增强、模型、分辨率和训练参数
   ↓
重新训练
   ↓
在独立测试集和困难样本集上验证
```

## 8. 推理参数优化 vs 训练优化

### 推理参数优化

推理参数优化**不会让模型变得更好**，它只控制最终的识别显示效果——相当于调整"通过标准"。

### 训练优化

训练优化才会让模型真正学会：

```
什么是目标
什么不是目标
不同类别之间有什么区别
遮挡时目标是什么样
小目标是什么样
复杂背景下目标是什么样
```

训练优化按优先级主要包括：

- 修正标注；
- 增加困难样本；
- 增加硬负样本；
- 调整类别分布；
- 调整数据增强；
- 调整模型大小；
- 调整训练分辨率；
- 调整学习率、训练轮数等超参数。

> [!warning] 别指望调 `conf` 把模型修好
> 用 `conf` 把误检压下去，往往只是把误检换成了漏检，指标此消彼长。**真正的改进来自训练侧。**

## 9. 数据增强应该怎么调整

### 1. Mosaic

将多张图片拼接组合到一张训练图。

优点：

- 增加多目标场景；
- 增加不同尺度目标；
- 提升复杂背景适应能力；
- 对小数据集有帮助。

缺点：

- 可能产生不自然场景；
- 目标可能被缩得很小；
- 可能增加边缘截断目标；
- 对精确定位可能产生干扰。

可以在最后若干轮通过 `close_mosaic` 关闭，让模型在后期适应更自然的图像。

### 2. MixUp

将两张图片按比例混合。

可能帮助：

- 提高鲁棒性；
- 减少过拟合；
- 增加一定遮挡效果。

但同时会造成视觉上不自然的图片，建议**尽量少用**。

### 3. 颜色增强

例如亮度、饱和度、色调。适当调整可用于解决：

- 光照变化；
- 不同摄像设备；
- 颜色偏差。

### 4. 翻转

有些目标可以相应翻转，用来覆盖真实场景中可能出现的姿态。

## 10. 什么时候增加训练轮数 `epochs`

增加 `epochs` 适合以下情况：

- 损失仍然明显下降；
- 验证指标仍然持续提高；
- 模型尚未收敛；
- 没有明显的过拟合。

> [!warning] 加 `epochs` 治不了数据问题
> 如果问题出在**样本缺失、标注错误或类别不平衡**，继续加轮数只会让模型更过拟合，不会凭空学会没见过的情况。

## 11. 错误分类表

| 错误类型 | 缩写 | 含义 | 优先优化方向 |
| --- | --- | --- | --- |
| 误检 | FP | 没有目标却检测到了 | 硬负样本、背景数据、漏标检查 |
| 漏检 | FN | 有目标却没检测到 | 困难样本、低置信度分析、遮挡样本 |
| 分类错误 | CLS | 框对了，类别错了 | 类别平衡、相似类样本、标注检查 |
| 定位错误 | LOC | 类别对了，框不准 | 标注框质量、分辨率、模型容量 |
| 重复检测 | DUP | 一个目标多个框 | NMS IoU、标注一致性 |
| 遮挡错误 | OCC | 遮挡目标漏检 | 遮挡和拥挤训练样本 |
| 小目标错误 | SMALL | 小目标漏检 | 小目标数据、裁剪、分辨率 |
| 领域错误 | DOMAIN | 特定环境表现差 | 收集目标环境真实数据 |

## 12. 最终判断规则

```
误检多：
先查漏标和硬负样本，再考虑提高 conf。

漏检多：
先降低 conf，看候选框是否存在；
如果候选框都不存在，再补充对应训练数据。

重叠目标漏检：
先降低 conf，再适当提高 iou；
长期方案是增加拥挤、遮挡、重叠训练样本。

重复框多：
适当降低 iou；
检查高分辨率和标注一致性。

小目标漏检：
增加小目标数据、合理裁剪；
必要时再提高 imgsz。

类别混淆：
增加容易混淆类别的对比样本；
检查类别平衡和错误标注。

框不准确：
优先检查标注框规范；
再考虑分辨率和模型容量。

特定环境表现差：
补充该环境的真实数据；
数据增强只能辅助，不能完全代替真实数据。

过拟合（随着轮数增加,训练损失持续下降但是验证损失几乎不变甚至反弹）：
早停，并查看相关验证指标进行针对性修改优化。
```

> [!note] 本课小结
> - `Precision` 看误检、`Recall` 看漏检；`mAP50-95` 比 `mAP50` 更能反映框的定位精度
> - 混淆矩阵 **行 = 预测（Predicted）、列 = 真实（True）**：最后一列是误检（FP），最后一行是漏检（FN）
> - PR 曲线越靠近右上角越好；F1 曲线最高点对应 P、R 最均衡的 `conf`
> - 误检先查漏标与硬负样本；漏检先降 `conf` 看候选框是否存在，再补数据
> - 推理参数（`conf` / `iou`）只改变显示效果，**训练优化才能让模型真正学会**；优先修标注、补困难样本与硬负样本
> - 数据增强各有副作用：Mosaic 后期用 `close_mosaic` 关闭、MixUp 少用、颜色增强治光照、翻转治姿态
> - 增加 `epochs` 不能替代补数据和修标注
