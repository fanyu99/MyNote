## 一、训练参数分类总览

### 1. 训练规模 / 数据相关

| 参数 | 作用 | 典型值 |
| --- | --- | --- |
| `epochs` | 训练轮数（完整看几遍全部数据） | `50~300` |
| `batch` | 一批送入多少张图 | `8~64`（受显存限制） |
| `imgsz` | 输入分辨率 | `640`（小目标可 `960/1280`） |
| `workers` | DataLoader 工作进程数 | Windows 卡加载时设 `0` |
| `device` | 训练设备（GPU/CPU） | `0` / `-1` / `cpu` |
| `cache` [[#★ cache / fraction / multi_scale / freeze\|★详解 →]] | 是否把图片缓存到内存/磁盘加速读取 | `False` / `ram` / `disk` |
| `patience` [[#★ 早停 patience\|★详解 →]] | 早停：验证指标多少轮不提升就停止 | `100`（`0`=关闭） |
| `fraction` [[#★ cache / fraction / multi_scale / freeze\|★详解 →]] | 仅用训练集的多少比例做训练 | `1.0` |
| `seed` / `deterministic` [[#★ seed 与 deterministic：复现性\|★详解 →]] | 随机种子与确定性模式，用于复现 | `0` / `True` |
| `resume` [[#★ resume：断点续训\|★详解 →]] | 从上次中断处继续训练 | `False` |

### 2. 优化器相关

| 参数 | 作用 | 典型值 |
| --- | --- | --- |
| `optimizer` [[#★ optimizer：SGD vs Adam vs AdamW\|★详解 →]] | 优化器类型（SGD / Adam / AdamW / auto） | `auto` |
| `lr0` | 初始学习率 | `0.01`（SGD）/ `0.001`（Adam） |
| `lrf` | 最终学习率倍率，最终 LR = `lr0 × lrf` | `0.01` |
| `momentum` | SGD 动量，加速收敛、平滑更新 | `0.937` |
| `weight_decay` [[#★ weight_decay：不只是防过拟合\|★详解 →]] | 权重衰减（L2 正则），防过拟合 | `0.0005` |
| `nesterov` [[#★ optimizer：SGD vs Adam vs AdamW\|★详解 →]] | 是否用 Nesterov 动量 | `True` |

### 3. 学习率调度 / 预热

| 参数 | 作用 | 典型值 |
| --- | --- | --- |
| `cos_lr` [[#★ 学习率调度：cos_lr 与 warmup\|★详解 →]] | 是否用余弦退火调度学习率 | `False` |
| `warmup_epochs` | 预热轮数：LR 从小升到 `lr0` | `3.0` |
| `warmup_momentum` | 预热阶段的动量 | `0.8` |
| `warmup_bias_lr` | 预热阶段偏置的初始学习率 | `0.1` |

### 4. 损失 / 样本匹配相关

| 参数 | 作用 | 典型值 |
| --- | --- | --- |
| `box` | 边界框回归损失权重 | `7.5` |
| `cls` | 分类损失权重 | `0.5` |
| `dfl` | 分布焦点损失权重（YOLOv8 有，YOLO26 已移除） | `1.5` |
| `label_smoothing` [[#★ label_smoothing：标签平滑\|★详解 →]] | 标签平滑，软化标签防过拟合 | `0.0` |
| `iou_t` | 正样本匹配 IoU 阈值 | `0.20` |

### 5. 正则化 / 防过拟合

| 参数 | 作用 | 备注 |
| --- | --- | --- |
| `dropout` | 随机丢弃神经元（主要分类任务） | 检测任务通常为 `0` |
| `weight_decay` | L2 正则，抑制权重过大 | 见上文 |
| `label_smoothing` | 标签软化 | 见上文 |
| `patience` | 早停 | 见上文 |
| 数据增强 | Mosaic / MixUp / HSV / 翻转等 | 见 [[YOLO第八课 训练结果分析,错误诊断与优化\|第八课 §9]] |

### 6. 模型容量 / 迁移学习

| 参数 | 作用 | 典型值 |
| --- | --- | --- |
| `model` | 模型规模 `n/s/m/l/x` 或 `.pt`/`.yaml` | `yolo26n.pt` |
| `pretrained` | 是否加载预训练权重 | 由 `.pt` 决定 |
| `freeze` [[#★ cache / fraction / multi_scale / freeze\|★详解 →]] | 冻结前 N 层（骨干），只微调头部 | `None` / 整数 |

### 7. 训练加速 / 稳定性

| 参数 | 作用 | 典型值 |
| --- | --- | --- |
| `amp` [[#★ amp：自动混合精度\|★详解 →]] | 自动混合精度（FP16+FP32），省显存加速 | `True` |
| `multi_scale` [[#★ cache / fraction / multi_scale / freeze\|★详解 →]] | 多尺度训练，随机改变输入尺寸 | `False` |
| 梯度裁剪 [[#★ 梯度裁剪（Gradient Clipping）\|★详解 →]] | 限制梯度范数，防爆炸 | 部分任务手动设置 |
| EMA [[#★ EMA：指数移动平均\|★详解 →]] | 指数移动平均权重，提升稳定与指标 | 默认开启 |

### 8. 数据增强（详见 [[YOLO第八课 训练结果分析,错误诊断与优化|第八课]]）

`hsv_h` / `hsv_s` / `hsv_v`、`degrees`、`translate`、`scale`、`shear`、`perspective`、`fliplr` / `flipud`、`mosaic`、`close_mosaic`、`mixup`、`copy_paste`、`erasing`。

## 二、笔记中缺少的重点参数详解

> 以下参数站内其它笔记基本未展开，这里重点说明。每节末尾可 [[#一、训练参数分类总览|↑ 返回总览]]。

### ★ optimizer：SGD vs Adam vs AdamW

| 优化器 | 特点 | 适用 |
| --- | --- | --- |
| **SGD + Momentum** | 收敛慢，但泛化往往更好、更稳，对超参敏感 | 目标检测传统默认，数据量大时 |
| **Adam** | 自适应学习率（一阶/二阶矩估计），收敛快 | 快速实验、小数据集 |
| **AdamW** | 修正 Adam 的权重衰减方式（解耦 L2） | Transformer、分类任务常用 |

> [!note] 为什么会有 AdamW
> 原始 Adam 把 L2 正则混进了梯度里，导致**权重衰减对自适应学习率失效**。AdamW 把权重衰减**解耦**出来直接作用在参数上，正则才真正生效。YOLO 默认 `optimizer='auto'`，会自行选择；传统检测训练常用 SGD。
>
> 基础用法（`torch.optim.SGD` / `Adam`）见 [[Pytorch学习#四、损失函数与优化器|PyTorch 第4章]]。

**补充要点（笔记未展开）**：
- **`lr0` 要跟着优化器换**：SGD 常用 `lr0≈0.01`，Adam/AdamW 要用更小的 `lr0≈0.001`（约为 SGD 的 1/10）。换优化器不换 `lr0` 是最常见的踩坑。
- **`nesterov`**：SGD 的动量开关。`nesterov=True` 用“先看下一步再修正”的 NAG 动量，通常比普通动量收敛略好；Adam 系优化器不受它影响（会忽略动量/`nesterov`）。
- **选择经验**：数据量大、追求最终精度 → SGD + 动量 + 余弦退火；样本少、想快速看效果 → Adam/AdamW；Transformer 结构优先 AdamW。

> ↑ [[#一、训练参数分类总览|返回总览]]

### ★ weight_decay：不只是防过拟合

权重衰减即 L2 正则，它在损失里加入 $\lambda\sum w^2$，**惩罚过大的权重**，让模型更平滑、降低过拟合风险。
- 太**小** → 正则不足，容易过拟合；
- 太**大** → 欠拟合，权重被过度压向 0。
- 注意：Adam 与 AdamW 对它的处理不同（见上）。

**补充要点**：
- Ultralytics 默认 `weight_decay=0.0005`；调参一般在 `1e-4 ~ 1e-3` 之间试。
- 它和 `dropout`、`label_smoothing` 同属**正则手段**，一般**不要同时都加大**，否则容易从过拟合滑到欠拟合。
- 与 L2 的关系：在标准 SGD 里 `weight_decay` 等价于 L2；在 Adam 里**不再等价**，这正是 AdamW 出现的原因。

> ↑ [[#一、训练参数分类总览|返回总览]]

### ★ label_smoothing：标签平滑

把硬标签 `[0, 0, 1, 0]` 软化为 `[ε, ε, 1-ε, ε]`。
- **作用**：防止模型对单一类别过度自信，缓解过拟合、提升泛化与置信度校准；
- **代价**：太小没效果，太大（如 >0.1）会让分类变模糊、学习变慢。
- 它与 [[YOLO第八课 训练结果分析,错误诊断与优化|第八课]] 的“高置信度误检”有一定关系：过度自信的模型更容易给出高置信误检。

**补充要点**：
- 默认 `label_smoothing=0.0`（关闭）；检测任务常取 `0.0~0.1`，分类任务用得更普遍。
- 数学上它把交叉熵的**硬目标换成软目标**，等价于给损失加了一点熵正则，抑制 logits 过大。

> ↑ [[#一、训练参数分类总览|返回总览]]

### ★ 学习率调度：cos_lr 与 warmup

- **预热 `warmup_epochs`**：训练初期权重随机、梯度可能很大，直接上大 `lr0` 容易**破坏预训练权重**或发散。warmup 让 LR 从极小值线性升到 `lr0`，稳定起步。
- **余弦退火 `cos_lr=True`**：LR 按余弦曲线从 `lr0` 平滑衰减到 `lr0 × lrf`，比线性衰减更平滑，后期小 LR 帮助精细收敛。
- 组合：`warmup`（升）→ 主训练（余弦/线性降）。

**补充要点**：
- 余弦曲线：$\eta_t=\eta_{min}+\tfrac{1}{2}(\eta_{max}-\eta_{min})\big(1+\cos(\tfrac{T_{cur}}{T_{max}}\pi)\big)$，最终 LR 由 `lrf` 决定（最终 LR = `lr0 × lrf`）。
- Ultralytics 默认 `warmup_epochs=3.0`、`warmup_momentum=0.8`、`warmup_bias_lr=0.1`；`cos_lr=False`（默认为线性式衰减）。
- 训练后期“卡住、loss 抖动、难以精修”时，打开 `cos_lr` 往往有改善。

> [!tip] 学习率设置不当的典型表现
> - **过大**：损失震荡、不下降甚至 NaN、参数发散；
> - **过小**：收敛极慢、卡在次优、训练很久还没到位。

> ↑ [[#一、训练参数分类总览|返回总览]]

### ★ 早停 patience

监控验证指标（如 fitness / mAP），**连续 `patience` 轮没有提升就提前停止**，避免过拟合与浪费算力。`patience=0` 关闭。
- 需配合 `save_period` / `best.pt`（见 [[YOLO第六课 YOLO训练实战|第六课]]）；
- 想续训用 `resume=True`（从 `last.pt` 继续）。

**补充要点**：
- Ultralytics 默认 `patience=100`（YOLOv8 起；更早版本默认 50）。
- “提升”按监控指标的**历史最优值**判断；小幅震荡不触发，只有连续无提升才停。
- 早停后**最好的权重是 `best.pt`，不是最后一轮的 `last.pt`**，别用错文件。

> [!warning] 早停不能替代修数据
> 如果问题来自样本缺失或标注错误，早停只是“止损”，不会让模型学会没见过的东西（同 [[YOLO第八课 训练结果分析,错误诊断与优化|第八课 §10]]）。

> ↑ [[#一、训练参数分类总览|返回总览]]

### ★ resume：断点续训

从上次中断处继续训练，用 `resume=True`（或 `resume=last.pt` 的路径）。模型会从 `runs/.../weights/last.pt` 恢复**权重、优化器状态、学习率调度与 epoch 计数**。

**补充要点**：
- 续训用于**训练被打断**（断电、崩溃、手动停），不是用来“接着换数据再练”——改了数据集/类别数后 `resume` 会报错或形同重训。
- 只想要权重、不想要优化器状态时，直接用 `.pt` 重新 `train` 更干净。
- 与 `patience` 配合：早停后还想多训几轮，用 `resume` 比新建训练更省事。

> ↑ [[#一、训练参数分类总览|返回总览]]

### ★ amp：自动混合精度

用 FP16 做前向/反向、FP32 保存主权重，**显存约减半、速度提升**，指标基本不掉。显存紧张或想提速时保持 `amp=True`（默认）。少数任务若出现 NaN/不稳定，可关闭 AMP 排查。

**补充要点**：
- Ultralytics 默认 `amp=True`；AMP 内部用**梯度缩放（GradScaler）**防止 FP16 下溢，遇到异常步会跳过更新。
- 排查 NaN 的顺序：**先关 `amp`** 看是否恢复——若恢复，多半是数值稳定性问题；若仍 NaN，再查学习率与异常标注。

> ↑ [[#一、训练参数分类总览|返回总览]]

### ★ 梯度裁剪（Gradient Clipping）

在反向传播后、更新参数前，**限制梯度的范数上限**（如 `clip_grad_norm_`）。当梯度爆炸（尤其 RNN/Transformer/深层网络）时，是简单有效的稳定手段。与“降低学习率”常配合使用。

**补充要点**：
- Ultralytics 训练**默认就开启范数裁剪，`max_norm` 通常为 `10.0`**——所以“梯度裁剪”在 YOLO 里多是**默认已生效**的隐藏手段。
- 两种写法：按范数裁剪 `clip_grad_norm_(params, max_norm)`（常用）、按值裁剪 `clip_grad_value_`。

> ↑ [[#一、训练参数分类总览|返回总览]]

### ★ EMA：指数移动平均

维护一份“参数的历史滑动平均”，推理/验证用 EMA 权重，通常**更平滑、指标更高、更稳**。它是 Ultralytics 训练里默认开启的“隐藏优化”，理解它有助于看懂 `best.pt` 的由来。

**补充要点**：
- 更新式：$\theta_{EMA}\leftarrow \alpha\,\theta_{EMA}+(1-\alpha)\,\theta$，$\alpha$ 越接近 1 越平滑（Ultralytics 相关默认约 `momentum=0.9999` / `tau≈2000`）。
- 训练早期 EMA 还在“追赶”，前几轮用它评估的指标可能偏低，属正常现象。

> ↑ [[#一、训练参数分类总览|返回总览]]

### ★ seed 与 deterministic：复现性

固定 `seed` 并开启 `deterministic`，可让数据打乱、初始化、增强尽量可复现，便于对比实验。代价是速度略降、且不保证跨硬件/跨版本完全一致。

**补充要点**：
- Ultralytics 默认 `seed=0`、`deterministic=True`。
- 仍不可复现的常见来源：`workers>0` 的多进程增强、cuDNN 非确定性算子、不同 GPU/驱动。要尽量复现可设 `workers=0` 并关闭 cuDNN benchmark。
- 复现性的目的是**控制变量做对比实验**，而不是要求逐位（bit-wise）相同。

> ↑ [[#一、训练参数分类总览|返回总览]]

### ★ cache / fraction / multi_scale / freeze

- **`cache`**：把图片缓存到 `ram`/`disk`，消除磁盘 IO 瓶颈。数据集大时谨慎用 `ram`（吃内存）。默认 `False`。
- **`fraction`**：只用部分训练数据（如 `0.1`），用于快速实验/调参。默认 `1.0`（全量）。
- **`multi_scale`**：训练时随机变换输入尺寸，提升对目标尺度变化的鲁棒性，代价是每步更慢。默认 `0.0`（关闭）。
- **`freeze`**：冻结骨干（前 N 层），只训练头部。小数据集 + 迁移学习时能**防过拟合、加速、省显存**。默认 `None`。

**补充要点**：
- `fraction` 常用于**冒烟测试/调参**：先用 0.1 数据跑通全流程，再上全量。
- `multi_scale` 只改输入尺寸、不做裁剪；对小目标友好，但会让 BN 统计与每步耗时产生波动。
- `freeze` 冻结的层数要与 `model` 规模匹配；冻结太多（如只剩检测头）会欠拟合，建议先小步试探。

## 三、常见训练问题与优化方向

> 这里按“**现象 → 原因 → 优化方向**”组织。推理侧问题（误检/漏检/重复框）见 [[YOLO第八课 训练结果分析,错误诊断与优化|第八课]]。本节可由第四节速查表跳入，末尾可 [[#四、症状 → 参数速查表（训练侧）|↑ 返回速查表]]。

### 1. 损失不下降 / 下降很慢
- **现象**：`box_loss`/`cls_loss` 长期几乎不动。
- **原因**：学习率过小；数据/标签错误（如标签全零、类别号错位）；模型容量不足；梯度消失；输入未归一化。
- **优化**：调大 `lr0`、加 warmup；**先检查标签与数据管线**；换更大模型；加 BN/残差；确认归一化。

### 2. 过拟合（训练降、验证升）
- **现象**：训练指标持续变好，验证指标停滞或变差（[[YOLO第八课 训练结果分析,错误诊断与优化|第八课 §12]] 已给出判断规则）。
- **原因**：数据太少/太单一；模型太大；训练太久。
- **优化**：
  - 增数据 + 数据增强（Mosaic/MixUp/HSV/翻转，见 [[YOLO第八课 训练结果分析,错误诊断与优化|第八课 §9]]）；
  - 加大 `weight_decay`、开启/加大 `dropout`、`label_smoothing`；
  - **早停 `patience`**、减小模型规模、`freeze` 骨干。
- **链接**：过拟合定义见 [[Pytorch学习#十三、图片归一化与训练集/验证集|PyTorch 第13章]]。

### 3. 欠拟合（训练、验证都差）
- **现象**：两边指标都低、损失降不下去。
- **原因**：模型太小/太简单；训练不够（`epochs` 太少）；正则化过强（`weight_decay`/`dropout` 太大）；学习率不合适；特征工程/输入有问题。
- **优化**：换更大模型、加 `epochs`、减小正则、调学习率、检查数据质量。
- **注意**：与“过拟合”是相反方向，别用错药（加大正则只会更糟）。

### 4. 损失出现 NaN(Not a Number) / inf
- **原因**：学习率过大导致发散；梯度爆炸；除零（IoU/宽高为 0）；AMP 数值不稳。
- **优化**：降低 `lr0`、加 warmup、开**梯度裁剪**；检查异常标注框（宽高为 0、越界）；可临时关 `amp` 排查。

### 5. 梯度消失 / 梯度爆炸 ★
- **梯度消失**：深层网络链式求导使梯度逐层变小 → 前层几乎不更新，深度难训练。
  - 解决：**BatchNorm**（[[Pytorch学习#九、批归一化 BatchNorm2d|PyTorch 第9章]]）、残差连接、合适初始化（He/Xavier）、换用非饱和激活（ReLU/SiLU，避免 Sigmoid/Tanh 堆叠）。
- **梯度爆炸**：梯度逐层放大 → 参数发散、loss NaN。
  - 解决：**梯度裁剪**、降低学习率、BN、warmup。

### 6. 训练不稳定、指标震荡
- **原因**：学习率过大；`batch` 太小噪声大；数据分布波动。
- **优化**：降低 `lr0`、增大 `batch`、warmup、EMA 平滑、固定 `seed`。

### 7. 显存不足（CUDA out of memory）
- **优化顺序**：减小 `batch` → 保持 `amp=True` → 降低 `imgsz` → 换更小的模型（`n`）→ `freeze` 骨干。
- **链接**：[[Pytorch学习#常见错误排查|PyTorch 常见错误排查]]、[[YOLO第六课 YOLO训练实战|第六课]]。

### 8. 训练 / 数据加载很慢
- **原因**：磁盘 IO 瓶颈（CPU/workers 不足）、数据增强过重、分辨率过高。
- **优化**：调大 `workers`（Windows 卡则设 `0` 排查）、`cache=ram`、降低 `imgsz`、精简增强。
- **排查**：GPU 利用率低而 CPU 满载 → 多半是数据加载瓶颈。

### 9. 类别不平衡 / 长尾
- **现象**：稀有类 Recall 很低，常见类挤占。
- **优化**：重采样（过采样稀有类/欠采样常见类）；类别加权损失；Focal Loss（降易分样本权重）；增加稀有类真实样本；调整类别分布（[[YOLO第八课 训练结果分析,错误诊断与优化|第八课 §8]]）。

### 10. 小目标检测差
- **优化**：提高 `imgsz`（`960/1280`）、增加小目标数据、合理裁剪（tiling）、`multi_scale` 训练、更高分辨率特征层。见 [[YOLO第八课 训练结果分析,错误诊断与优化|第八课 §6]]。

### 11. 收敛慢 / 学不动
- **优化**：加 warmup、用余弦退火、适当调大 `lr0`、检查归一化与初始化、换优化器（SGD→Adam 快速实验）、加 `epochs`。

### 12. 领域偏移 / 数据泄漏 ★
- **原因**：
  - **领域偏移**：验证集与真实场景分布不同（光照、设备、背景）；
  - **数据泄漏**：训练/验证集有重复或高度相似的图片，指标虚高。
- **优化**：验证集要**独立且贴合部署场景**；补充真实场景数据；检查去重与划分方式；数据增强只能辅助、不能替代真实数据。

## 五、训练优化优先级（结论）

```
1. 修数据：查标签、去重、防数据泄漏    ← 收益最大，先做
2. 补样本：困难样本、硬负样本、稀有类、真实场景数据
3. 调增强：Mosaic / MixUp / HSV / 翻转（治光照、姿态、尺度）
4. 换模型：容量 n→s→m、必要时 freeze 骨干
5. 调分辨率 imgsz 与 batch
6. 调超参：lr0 / lrf / weight_decay / dropout / label_smoothing
7. 用技巧：warmup / 余弦退火 / AMP / 梯度裁剪 / EMA / 早停
```

> [!warning] 顺序别倒过来
> 很多人一上来就狂调学习率，收益却很低。**数据 > 增强 > 模型 > 超参**——超参调优是最后一步，不是第一步。推理参数的 `conf`/`iou` 更只是“显示阈值”，改不了一个坏模型（[[YOLO第八课 训练结果分析,错误诊断与优化|第八课 §8]]）。

> [!note] 小结
> - 训练参数分八类：规模/优化器/调度/损失/正则/容量/加速/增强
> - 站内缺的重点：`optimizer` 取舍、`weight_decay` 本质、`label_smoothing`、学习率调度与 warmup、`patience` 早停、`resume` 续训、AMP、梯度裁剪、EMA、复现性、`freeze`/`cache`/`fraction`/`multi_scale`
> - 训练问题按“现象→原因→优化”定位，**先数据后超参**
> - 过拟合 ≠ 欠拟合，药不能下反；NaN/爆炸先降 LR + 裁剪
> - 领域偏移与数据泄漏会让验证指标虚高，务必用独立、贴合场景的验证集
